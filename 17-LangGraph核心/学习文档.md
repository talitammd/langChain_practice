# 第17节：LangGraph 核心 — 图编排、状态机、为什么 92% 岗位要它

## 一、本节定位

上节搞清了 LangChain 的定位：基础设施层。本节进入 Agent 编排的主战场——**LangGraph**。它用状态图（StateGraph）替代了 AgentExecutor 的黑盒循环，让 Agent 的每一步推理都变成图上可检查、可恢复的节点。本节目标：理解 StateGraph 的核心概念（State、Node、Edge），能手写一个带工具调用和循环的 ReAct Agent。

---

## 二、为什么需要 LangGraph

### 2.1 AgentExecutor 的死穴

```python
# AgentExecutor 本质上是这样一个循环
while not done and iterations < max_iterations:
    action = llm.predict(prompt)    # 黑盒：不知道模型想了什么
    result = execute_tool(action)   # 黑盒：失败了怎么处理？
    prompt += result                # 黑盒：上下文怎么管理？
    iterations += 1
```

问题在于：你无法在循环中间插入自定义逻辑、无法根据不同结果走不同分支、无法暂停等人确认、进程崩了无法恢复。

### 2.2 LangGraph 的解法

把隐式循环变成**显式状态图**：

```
         ┌──────────────────────────┐
         │                          │
         ▼                          │
    ┌─────────┐    有工具调用   ┌─────────┐
    │  Agent  │──────────────→│  Tools  │
    │  (LLM)  │               │(执行工具)│
    └─────────┘               └─────────┘
         │
         │ 无工具调用（最终回答）
         ▼
       END
```

每个框是一个**节点（Node）**，箭头是**边（Edge）**，从 Agent 到 Tools 的箭头上有**条件判断**。整个图有一个全局**状态（State）**在节点之间传递。

## 三、核心概念

### 3.1 State（状态）

状态是图运行期间所有节点共享的数据结构。用 `TypedDict` 或 `Pydantic BaseModel` 定义：

```python
from typing import TypedDict, Annotated
from langgraph.graph import add_messages

class AgentState(TypedDict):
    """Agent 的全局状态"""
    messages: Annotated[list, add_messages]  # 对话历史（自动合并）
    current_step: str                         # 当前处于哪一步
    tool_call_count: int                      # 工具调用次数（用于限流）
```

**`Annotated[list, add_messages]`** 是 LangGraph 的精华设计——`add_messages` 是一个 **reducer 函数**，定义了当多个节点都往 `messages` 里写数据时如何合并（追加而非覆盖）。

```python
# Reducer 的作用
# 如果没有 reducer，节点返回 {"messages": [new_msg]} 会覆盖整个列表
# 有了 add_messages reducer，新消息会追加到已有列表末尾
# 还能根据 ID 去重（相同 ID 的消息会被替换而非重复添加）
```

### 3.2 Node（节点）

节点就是**普通 Python 函数**，接收 State，返回要更新的 State 部分：

```python
from langchain_openai import ChatOpenAI

model = ChatOpenAI(model="gpt-4o")

def agent_node(state: AgentState) -> dict:
    """Agent 节点：调用 LLM 生成回复"""
    response = model.invoke(state["messages"])
    return {"messages": [response]}  # 返回的部分会通过 reducer 合并到 State

def tool_node(state: AgentState) -> dict:
    """工具节点：执行 LLM 请求的工具调用"""
    last_message = state["messages"][-1]
    results = []
    for tool_call in last_message.tool_calls:
        result = execute_tool(tool_call)  # 你的工具执行逻辑
        results.append(ToolMessage(
            content=str(result),
            tool_call_id=tool_call["id"]
        ))
    return {"messages": results}
```

**注意**：节点不需要返回完整 State，只返回需要更新的字段。LangGraph 会用 reducer 把返回值合并到全局 State。

### 3.3 Edge（边）

边定义节点之间的连接。有三种类型：

```python
from langgraph.graph import StateGraph, END

graph = StateGraph(AgentState)

# 1. 普通边：A 执行完一定走 B
graph.add_edge("tools", "agent")

# 2. 条件边：根据当前状态决定下一步走哪
def should_continue(state: AgentState) -> str:
    last_message = state["messages"][-1]
    if last_message.tool_calls:
        return "tools"    # 有工具调用 → 去执行工具
    return END            # 没有工具调用 → 结束

graph.add_conditional_edges("agent", should_continue)

# 3. 入口边：图从哪个节点开始
graph.set_entry_point("agent")
```

### 3.4 编译与运行

```python
# 编译图（生成可执行的 Runnable）
app = graph.compile()

# 运行
result = app.invoke({
    "messages": [HumanMessage(content="北京今天天气怎么样？")]
})

# 流式运行（看到每一步的状态变化）
for event in app.stream({"messages": [HumanMessage(content="查一下比特币价格")]}):
    for node_name, output in event.items():
        print(f"--- {node_name} ---")
        print(output)
```

## 四、完整实战：用 LangGraph 实现 ReAct Agent

```python
"""
用 LangGraph 实现一个完整的 ReAct Agent
比 AgentExecutor 更透明、更可控
"""
from typing import TypedDict, Annotated
from langchain_openai import ChatOpenAI
from langchain_core.messages import HumanMessage, AIMessage, ToolMessage
from langgraph.graph import StateGraph, END, add_messages
import json

# ===== 1. 定义状态 =====
class AgentState(TypedDict):
    messages: Annotated[list, add_messages]

# ===== 2. 定义工具 =====
def get_weather(city: str) -> str:
    """获取城市天气（模拟）"""
    weather_data = {"北京": "晴，32°C", "上海": "多云，28°C", "深圳": "雷阵雨，30°C"}
    return weather_data.get(city, f"未找到 {city} 的天气数据")

def search_web(query: str) -> str:
    """网络搜索（模拟）"""
    return f"搜索结果：关于 '{query}' 的最新信息..."

# 工具注册表
tools = {
    "get_weather": get_weather,
    "search_web": search_web,
}

# 工具的 JSON Schema（给模型看）
tool_schemas = [
    {
        "type": "function",
        "function": {
            "name": "get_weather",
            "description": "获取指定城市的天气信息",
            "parameters": {
                "type": "object",
                "properties": {"city": {"type": "string", "description": "城市名"}},
                "required": ["city"]
            }
        }
    },
    {
        "type": "function",
        "function": {
            "name": "search_web",
            "description": "搜索网络获取信息",
            "parameters": {
                "type": "object",
                "properties": {"query": {"type": "string", "description": "搜索关键词"}},
                "required": ["query"]
            }
        }
    }
]

# ===== 3. 定义节点 =====
model = ChatOpenAI(model="gpt-4o").bind_tools(tool_schemas)

def agent_node(state: AgentState) -> dict:
    """Agent 节点：调用 LLM"""
    response = model.invoke(state["messages"])
    return {"messages": [response]}

def tool_node(state: AgentState) -> dict:
    """工具节点：执行所有待处理的工具调用"""
    last_message = state["messages"][-1]
    results = []
    for call in last_message.tool_calls:
        func = tools[call["name"]]
        # 解析参数并执行
        result = func(**call["args"])
        results.append(ToolMessage(
            content=str(result),
            tool_call_id=call["id"],
        ))
    return {"messages": results}

# ===== 4. 定义条件边 =====
def should_continue(state: AgentState) -> str:
    last_message = state["messages"][-1]
    if hasattr(last_message, "tool_calls") and last_message.tool_calls:
        return "tools"
    return END

# ===== 5. 组装图 =====
graph = StateGraph(AgentState)
graph.add_node("agent", agent_node)
graph.add_node("tools", tool_node)
graph.set_entry_point("agent")
graph.add_conditional_edges("agent", should_continue)
graph.add_edge("tools", "agent")  # 工具执行完回到 Agent

app = graph.compile()

# ===== 6. 运行并观察每一步 =====
def run_agent(question: str):
    print(f"\n{'='*60}")
    print(f"用户问题: {question}")
    print('='*60)
    
    for event in app.stream(
        {"messages": [HumanMessage(content=question)]},
        stream_mode="updates"
    ):
        for node_name, output in event.items():
            print(f"\n--- 节点: {node_name} ---")
            for msg in output.get("messages", []):
                if hasattr(msg, "tool_calls") and msg.tool_calls:
                    for tc in msg.tool_calls:
                        print(f"  工具调用: {tc['name']}({tc['args']})")
                elif isinstance(msg, ToolMessage):
                    print(f"  工具结果: {msg.content}")
                else:
                    print(f"  回复: {msg.content}")

# 测试
run_agent("北京和上海今天天气怎么样？")
# 输出会清晰展示：
# --- 节点: agent ---
#   工具调用: get_weather({"city": "北京"})
#   工具调用: get_weather({"city": "上海"})
# --- 节点: tools ---
#   工具结果: 晴，32°C
#   工具结果: 多云，28°C
# --- 节点: agent ---
#   回复: 北京今天晴，32°C；上海多云，28°C。
```

## 五、与 AgentExecutor 的对比

| 维度 | AgentExecutor | LangGraph StateGraph |
|------|--------------|---------------------|
| 控制流可见性 | 黑盒 while 循环 | 可视化状态图 |
| 中间状态 | 不可访问 | stream_mode="updates" 逐步可见 |
| 条件分支 | 不支持 | add_conditional_edges 原生支持 |
| 人工介入 | 不支持 | interrupt() 原生支持（下节详讲） |
| 持久化 | 不支持 | Checkpointer 自动保存/恢复 |
| 错误处理 | 全局 try/except | 每个节点独立处理 |
| 并行执行 | 不支持 | 多条边同时触发 |
| 代码量 | 少（但出问题代价大） | 稍多（但每一步透明） |

## 六、Checkpointer：状态持久化

LangGraph 的杀手功能之一——每一步的状态自动保存，进程崩了可以从断点恢复：

```python
from langgraph.checkpoint.memory import MemorySaver

# 使用内存存储（生产用 PostgreSQL/Redis）
checkpointer = MemorySaver()
app = graph.compile(checkpointer=checkpointer)

# 运行时指定 thread_id，用于标识一次会话
config = {"configurable": {"thread_id": "user-123"}}

# 第一次调用
result = app.invoke(
    {"messages": [HumanMessage(content="你好")]},
    config=config
)

# 第二次调用——自动恢复之前的对话历史
result = app.invoke(
    {"messages": [HumanMessage(content="我刚才说了什么？")]},
    config=config
)
# Agent 能记住上一轮的对话，因为 Checkpointer 自动加载了之前的 State

# 获取某个时间点的状态快照
snapshot = app.get_state(config)
print(snapshot.values["messages"])  # 完整对话历史
```

**生产级 Checkpointer 选择**：

| 存储 | 适用场景 | 包 |
|------|---------|---|
| MemorySaver | 本地开发/测试 | langgraph（内置） |
| SqliteSaver | 单机持久化 | langgraph-checkpoint-sqlite |
| PostgresSaver | 多实例生产部署 | langgraph-checkpoint-postgres |

## 八、小结 & 下节预告

LangGraph 的核心就三件事：**State 定义数据、Node 定义行为、Edge 定义流转**。比起 AgentExecutor，它把 Agent 的控制流从黑盒循环变成了显式状态图，每一步都可检查、可恢复、可分支。Checkpointer 解决了生产中最头疼的状态持久化问题——进程崩了不用从头来。

但到目前为止我们的图还很简单——一个 Agent 节点加一个 Tools 节点。真实场景里你会遇到条件分支（根据不同的工具结果走不同路径）、循环控制（某些步骤需要重试或回退）、人工介入（关键操作暂停等人确认）。这些就是下节课 LangGraph 进阶的内容。

## 九、答案要点

<details>
<summary>概念自测参考答案</summary>

**1.** State 是图运行期间所有节点共享的数据结构，定义了 Agent 需要跟踪的所有信息；Node 是处理逻辑的承载单元，每个节点是一个接收 State 返回 State 更新的函数；Edge 定义节点之间的连接和流转规则，决定执行完一个节点后下一步去哪。

**2.** `add_messages` 是一个 reducer 函数，它定义了当多个节点都向 `messages` 字段写入数据时的合并策略——追加而非覆盖。如果没有 reducer，后一个节点返回的 messages 会覆盖前一个节点写入的，导致对话历史丢失。add_messages 还支持按消息 ID 去重，相同 ID 的消息会被替换。

**3.** 普通边是无条件连接，A 节点执行完一定走到 B 节点；条件边会调用一个判断函数，根据当前 State 返回下一个要走的节点名称（字符串），实现运行时的动态路由。

**4.** Checkpointer 在每个节点执行后自动保存当前 State 的快照。生产中需要它的原因：① 进程崩溃后可以从断点恢复，不用从头运行；② 支持 Human-in-the-loop，暂停图执行等人确认后继续；③ 跨请求保持对话状态（通过 thread_id 关联）；④ 支持状态回溯和调试。

**6.** 添加计算工具：
```python
def calculate(expression: str) -> str:
    """安全地计算数学表达式"""
    try:
        # 只允许数字和基本运算符，防止代码注入
        allowed = set("0123456789+-*/.() ")
        if not all(c in allowed for c in expression):
            return "错误：表达式包含非法字符"
        result = eval(expression)  # 生产中用 sympy 或 ast.literal_eval
        return str(result)
    except Exception as e:
        return f"计算错误：{e}"

tools["calculate"] = calculate
# 同时在 tool_schemas 中添加对应的 schema
```
