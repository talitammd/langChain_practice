# 第14节：反思与自我修正

## 一、本节定位

前面所有范式都是"生成一次就完"——ReAct 做完一轮进下一轮，Plan-and-Execute 执行完收工。但真实场景里 Agent 第一版输出往往有问题。本节解决：**Agent 能不能自己发现错误、自己改？**

---

## 二、核心范式对比

| 范式          | 核心思想       | 何时反思  | 依赖外部信号 | 面试频率  |
| ----------- | ---------- | ----- | ------ | ----- |
| Reflection  | 自我审查输出     | 输出后   | 否      | ⭐⭐    |
| Reflexion   | 反思+情景记忆    | 执行失败后 | 可选     | ⭐⭐⭐⭐⭐ |
| Self-Refine | 生成-批评-修改循环 | 输出提交前 | 否      | ⭐⭐⭐   |
| CRITIC      | 自我批评+工具验证  | 输出后   | 是（必须）  | ⭐⭐⭐   |

---

## 三、Reflection（基础反思）

### 3.1 流程

```
生成输出 → 自我审查 → "有没有问题？" → 输出最终结果
```

### 3.2 实现

```python
def reflection_step(output: str, task: str) -> str:
    """让模型审查自己的输出"""
    critique = openai.chat.completions.create(
        model="gpt-4o",
        messages=[
            {"role": "system", "content": "你是代码审查员。检查以下输出是否有错误。"},
            {"role": "user", "content": f"任务: {task}\n输出: {output}\n\n请检查是否有错误，如果没有就说'无需修改'。"}
        ],
    )
    feedback = critique.choices[0].message.content
    if "无需修改" in feedback:
        return output
    # 根据反馈修改
    revised = openai.chat.completions.create(
        model="gpt-4o",
        messages=[
            {"role": "system", "content": "根据反馈修改输出。"},
            {"role": "user", "content": f"原输出: {output}\n反馈: {feedback}\n请修改。"}
        ],
    )
    return revised.choices[0].message.content
```

### 3.3 陷阱：自我确认偏差

模型审查自己的输出时倾向于觉得"没问题"。纯自我审查的改进幅度有限，尤其在模型能力较弱的领域。

## 四、Reflexion（面试重点）

### 4.1 核心创新

Reflexion = Reflection + 两个增强：

1. **口头反思（Verbal Reflection）**：不只说"有错"，而是具体写出"我哪里错了、为什么错、下次怎么做"
2. **情景记忆（Episodic Memory）**：把反思结论存下来，下一轮尝试时塞进上下文

### 4.2 完整流程

```
┌─────────────────────────────────────────┐
│           Reflexion 完整流程             │
│                                         │
│  1. 生成 (Generate)                     │
│     ↓                                   │
│  2. 评估 (Evaluate)                     │
│     ├── 外部工具评估（跑测试/执行代码）   │
│     └── 另一个 LLM 当裁判               │
│     ↓                                   │
│  3. 反思 (Reflect)                      │
│     → 产出自然语言"经验教训"             │
│     → 存入情景记忆                       │
│     ↓                                   │
│  4. 重试 (Retry)                        │
│     → 把历史反思塞进 prompt              │
│     → 带着教训重新生成                   │
│     ↓                                   │
│  循环直到成功或达到最大重试次数           │
└─────────────────────────────────────────┘
```

### 4.3 代码实现

```python
class ReflexionAgent:
    def __init__(self, max_attempts: int = 3):
        self.max_attempts = max_attempts
        self.reflections: list[str] = []  # 情景记忆

    def run(self, task: str, evaluator) -> str:
        """
        task: 任务描述
        evaluator: 评估函数，返回 (success: bool, feedback: str)
        """
        for attempt in range(self.max_attempts):
            # 构建 prompt，注入历史反思
            reflection_context = self._build_reflection_context()
            
            # 生成
            output = self._generate(task, reflection_context)
            
            # 评估
            success, feedback = evaluator(output)
            if success:
                return output
            
            # 反思：具体写出错在哪、为什么、下次怎么做
            reflection = self._reflect(task, output, feedback)
            self.reflections.append(reflection)
            print(f"[Reflexion] 第{attempt+1}次尝试失败，反思: {reflection[:100]}...")
        
        return output  # 返回最后一次输出

    def _build_reflection_context(self) -> str:
        if not self.reflections:
            return ""
        return "\n".join([
            f"过去的尝试经验（请避免同样的错误）:"
        ] + [f"- {r}" for r in self.reflections])

    def _generate(self, task: str, reflection_context: str) -> str:
        messages = [{"role": "system", "content": "你是一个任务执行Agent。"}]
        if reflection_context:
            messages.append({"role": "user", "content": reflection_context})
        messages.append({"role": "user", "content": f"任务: {task}"})
        
        response = openai.chat.completions.create(model="gpt-4o", messages=messages)
        return response.choices[0].message.content

    def _reflect(self, task: str, output: str, feedback: str) -> str:
        """生成具体的口头反思"""
        response = openai.chat.completions.create(
            model="gpt-4o",
            messages=[{
                "role": "user",
                "content": f"""任务: {task}
你的输出: {output}
反馈: {feedback}

请具体反思：
1. 我哪里错了？
2. 为什么会错？
3. 下次应该怎么做？

用简洁的语言写出经验教训。"""
            }],
        )
        return response.choices[0].message.content
```

### 4.4 评估器示例

```python
# 外部工具评估：执行代码看结果
def code_evaluator(code: str) -> tuple[bool, str]:
    try:
        exec(code)
        return True, "代码执行成功"
    except Exception as e:
        return False, f"执行报错: {type(e).__name__}: {e}"

# LLM 裁判评估
def llm_evaluator(output: str) -> tuple[bool, str]:
    response = openai.chat.completions.create(
        model="gpt-4o",
        messages=[{
            "role": "user",
            "content": f"评估以下输出是否正确且完整。输出: {output}"
        }],
    )
    result = response.choices[0].message.content
    success = "正确" in result and "错误" not in result
    return success, result
```

## 五、Self-Refine

### 5.1 流程

```
生成 → 批评 → 修改 → 批评 → 修改 → ... → 满意 → 输出
```

### 5.2 与 Reflexion 的区别

| 维度 | Reflexion | Self-Refine |
|------|-----------|-------------|
| 何时反思 | 执行失败后 | 输出提交前 |
| 外部信号 | 可选 | 不需要 |
| 目标 | 不犯同样的错 | 多轮打磨质量 |
| 停止条件 | 评估通过 | 批评环节输出"无需修改" |
| 适合场景 | 代码/推理任务 | 文案/创作任务 |

### 5.3 实现

```python
def self_refine(task: str, max_rounds: int = 3) -> str:
    # 生成初始版本
    output = llm_generate(task)
    
    for round_num in range(max_rounds):
        # 批评
        critique = llm_critique(output, task)
        if "无需修改" in critique:
            print(f"[Self-Refine] 第{round_num+1}轮：无需修改，完成")
            break
        
        # 修改
        output = llm_refine(output, critique)
        print(f"[Self-Refine] 第{round_num+1}轮：已修改")
    
    return output
```

## 六、CRITIC（外部工具验证）

### 6.1 核心思想

自我修正不能只靠自己，得用外部工具验证：

```
生成输出 → 自我批评 + 外部工具验证 → 根据反馈修正
              ↑                        ↓
              └────────────────────────┘
```

### 6.2 验证工具示例

| 输出类型 | 验证工具 |
|----------|----------|
| 事实陈述 | 搜索引擎（Google/Bing API） |
| 代码 | 执行器（Python REPL） |
| 数学推导 | 计算器（SymPy） |
| SQL 查询 | 在测试库上执行 EXPLAIN |
| 翻译 | 回译验证（翻译回去看一致不） |

## 七、自我修正的局限性（面试必问）

### 7.1 什么时候无效？

2024 年重要研究发现：**在模型能力较弱的场景下，自我修正反而降低性能。**

原因：模型连正确答案都认不出来，越改越差。

### 7.2 有效的前提条件

1. **有外部反馈信号**：测试通过、工具验证、用户反馈
2. **模型在审查任务上能力强于生成任务**：审查是"判断对错"，比"从零生成"容易
3. **有明确的停止条件**：避免无限循环烧 token

### 7.3 工程最佳实践

```
优先级:
1. 外部工具评估 > LLM 自评
2. 另一个更强的模型评估 > 同模型自评
3. 有外部信号的 Reflexion > 纯自我审查的 Reflection
4. 设最大重试次数（3次），避免死循环
```

## 八、面试高频题

### 题目 1：Reflexion 和 Self-Refine 有什么区别？

**标准答案**：Reflexion 是"执行失败后反思"——生成→评估→反思→重试，核心创新是口头反思加情景记忆，把"错在哪了"写下来存起来下次不犯同样的错。Self-Refine 是"输出提交前打磨"——生成→批评→修改循环，不需要外部信号，适合文案创作类任务。区别在于：Reflexion 依赖外部评估信号，目标是"不犯同样的错"；Self-Refine 不依赖外部信号，目标是"多轮提升质量"。

---

### 题目 2：自我修正一定有效吗？

**标准答案**：不一定。2024 年研究表明，模型能力较弱的场景下自我修正反而降低性能——因为模型连正确答案都认不出来，越改越差。有效的前提是：要么有外部反馈信号（测试通过、工具验证），要么模型在审查任务上的能力强于生成任务。工程实践中优先用外部工具做评估，而不是让模型自己评自己。同时要设最大重试次数避免死循环。

---

### 题目 3：Reflexion 的情景记忆和我们前面讲的记忆系统是什么关系？

**标准答案**：Reflexion 的情景记忆是第11节讲的四层记忆模型中"情景记忆"的具体应用——记录"我上次尝试时犯了什么错"。它跟长期记忆的区别是：情景记忆按事件存储，有过期性（这次任务的反思不一定适用于下次任务）。工程实现上可以把 Reflexion 的反思存入向量数据库，但要注意设过期时间，避免跨任务的反思互相干扰。

---

### 题目 4：CRITIC 范式怎么用外部工具验证？

**标准答案**：CRITIC 的核心是"自我批评+外部工具验证"。生成输出后，用对应类型的外部工具验证：事实陈述用搜索引擎验证、代码用 REPL 执行验证、数学推导用计算器验证。根据验证结果决定是否需要修正。这比纯自我审查靠谱，因为外部工具提供的是客观信号，不受模型自我确认偏差影响。

---

### 题目 5：你在项目里怎么实现反思机制的？讲讲具体设计。

**标准答案**：我在项目中实现了基于 Reflexion 的代码生成 Agent。流程是：Agent 生成代码→用沙箱执行跑测试用例→如果失败，让 LLM 生成具体反思（错在哪、为什么、怎么办）→存入情景记忆→重试时把历史反思注入 prompt。设了最大重试 3 次。关键设计点：评估用外部执行器而不是 LLM 自评，因为代码执行结果是客观信号；反思存入向量库但设了过期时间，避免跨任务干扰。
