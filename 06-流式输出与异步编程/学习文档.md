# 第06节 · 流式输出与异步编程

> 配套学习文档｜面试导向｜含代码示例与练习题

---

## 一、本节定位：从"干等五秒"到"边生成边看"

上一节我们给 Agent 装上了 Function Calling 这双手。但如果每次调用模型都要等几百上千个 token 全部生成完才返回，用户看到的就是五秒白屏 + 一大坨文字扑脸——体验像网页卡了一样。

**流式输出（Streaming）** 的核心就一句话：让模型边生成边往前端推 token，用户看到文字一个个蹦出来。它把首字延迟从 3~5 秒压到 200~500 毫秒——一样的总耗时，体验天差地别。

而流式输出的底层实现、高并发下的性能保证，都离不开 **异步编程（async/await）**。这一节把"流式 + 异步"这对搭档从原理到生产坑位全讲透。

---

## 二、核心知识讲解

### 2.1 SSE vs WebSocket：怎么选？

面试高频选型题：为什么 ChatGPT / Claude 都用 SSE 而不是 WebSocket？

| 对比维度 | SSE (Server-Sent Events) | WebSocket |
|---|---|---|
| **方向** | 单向（服务端 → 客户端） | 双向 |
| **协议** | 基于 HTTP/1.1 长连接 | 独立协议（ws://） |
| **浏览器** | 原生 EventSource，开箱即用 | 需要手动管理连接 |
| **复杂度** | 轻量，自动重连 | 较重，需心跳/重连 |
| **适用场景** | LLM 流式输出、日志推送 | 实时聊天、协作编辑、语音 |

**一句话结论**：大模型流式输出是典型的单向数据流，SSE 足够且更轻量。只有需要双向交互（如语音对话、实时协作）才上 WebSocket。

SSE 协议要点：响应 Content-Type 为 `text/event-stream`，每个事件格式为 `data: {json}\n\n`，结束时发送 `data: [DONE]\n\n`。

### 2.2 async/await：为什么在 Agent 里必用

大模型 API 调用是典型的 **IO 密集型**——你发出请求后，90% 时间在等网络。如果用同步代码，一个请求等着 → 线程阻塞 → 无法处理其他请求。

async/await 的核心价值：**在等 IO 的时候让出控制权**，让事件循环去处理别的协程。一个线程就能并发扛几十上百个请求，不用开多线程/多进程。

在 Agent 里，异步的典型场景：

- 并行工具调用（上一节）：`asyncio.gather(*[call_tool(c) for c in calls])`
- 流式接收 token：`async for chunk in stream`
- 批量并发调模型（如 Eval 评测）：同时跑几十条 case

### 2.3 生产三件套：限流、超时、错误隔离

异步编程写 Demo 很简单，但上生产一定会踩的三个坑：

| 坑          | 后果                          | 解法                                   |
| ---------- | --------------------------- | ------------------------------------ |
| **不做限流**   | 并发太猛，API 返回 429（Rate Limit） | `asyncio.Semaphore(n)` 控制并发上限        |
| **不做超时**   | 一个慢请求卡住，其他任务等死              | `asyncio.wait_for(coro, timeout=30)` |
| **不做错误隔离** | 一个协程抛异常，整批任务 cancel         | 每个协程内 `try/except`，不让单点失败扩散          |

面试里讲出这三点，就说明你真写过异步的生产代码，而不是只跑过 hello world。

### 2.4 流式 + 工具调用的合并处理

一个实战工程细节：流式输出时模型中途触发工具调用怎么办？

- Stream 里会收到带 `tool_calls` 的 chunk（delta 格式，分片到达）；
- 你要**攒起来**，把分片拼成完整的函数名 + 参数；
- 拼完后执行工具、回填结果，再继续 stream 后续文本。

这是实际写 Agent 代码时绑不开的场景——流式不是只输出文本，它和工具调用是交织在一起的。

## 三、代码示例

### 示例 1：流式调用 OpenAI + 逐 token 打印（最小版）

```python
from openai import OpenAI

client = OpenAI()

stream = client.chat.completions.create(
    model="gpt-4o",
    messages=[{"role": "user", "content": "用一句话解释什么是 Agent"}],
    stream=True,   # ← 开启流式
)

# 逐 chunk 接收并输出
for chunk in stream:
    delta = chunk.choices[0].delta
    if delta.content:
        print(delta.content, end="", flush=True)
print()  # 换行
```

**工程要点**：`stream=True` 让 SDK 返回一个可迭代对象，每次 yield 一个 chunk。`flush=True` 让终端立刻刷新——不加的话可能看不到逐字效果。

### 示例 2：FastAPI SSE 端点 + async generator

```python
from fastapi import FastAPI
from fastapi.responses import StreamingResponse
from openai import AsyncOpenAI
import asyncio

app = FastAPI()
aclient = AsyncOpenAI()

async def stream_llm(prompt: str):
    """异步生成器：逐 chunk 产出 SSE 格式数据"""
    stream = await aclient.chat.completions.create(
        model="gpt-4o",
        messages=[{"role": "user", "content": prompt}],
        stream=True,
    )
    async for chunk in stream:
        content = chunk.choices[0].delta.content
        if content:
            yield f"data: {content}\n\n"     # SSE 格式
    yield "data: [DONE]\n\n"

@app.get("/chat")
async def chat(q: str):
    return StreamingResponse(
        stream_llm(q),
        media_type="text/event-stream",
    )

# 前端用 EventSource("/chat?q=...") 即可逐字接收
```

**工程要点**：用 `AsyncOpenAI`（异步客户端）+ `async for` 接收流，每个 chunk 包成 SSE 格式 `data: ...\n\n`。FastAPI 的 `StreamingResponse` 配合 async generator 天然支持流式响应。

### 示例 3：生产三件套——Semaphore 限流 + 超时 + 错误隔离

```python
import asyncio
from openai import AsyncOpenAI

aclient = AsyncOpenAI()
SEM = asyncio.Semaphore(5)   # 最多并发 5 个请求

async def call_with_guard(prompt: str, timeout: float = 30.0) -> str:
    """带限流、超时、错误隔离的安全调用"""
    async with SEM:                                    # 1. 限流
        try:
            resp = await asyncio.wait_for(             # 2. 超时
                aclient.chat.completions.create(
                    model="gpt-4o",
                    messages=[{"role": "user", "content": prompt}],
                ),
                timeout=timeout,
            )
            return resp.choices[0].message.content
        except asyncio.TimeoutError:
            return f"[超时] {prompt[:20]}..."
        except Exception as e:                          # 3. 错误隔离
            return f"[错误] {type(e).__name__}: {e}"

async def batch_eval(prompts: list[str]) -> list[str]:
    """批量并发调用，互不影响"""
    tasks = [call_with_guard(p) for p in prompts]
    return await asyncio.gather(*tasks)

# asyncio.run(batch_eval(["问题1", "问题2", ..., "问题50"]))
```

**工程要点**：`Semaphore(5)` 保证同时最多 5 个请求在飞（防 429）；`wait_for` 30 秒超时（防卡死）；`try/except` 让单条失败返回错误标记而不影响其他任务。这三件套是 Agent 生产代码的标配。

### 示例 4：流式中攒 tool_calls 分片

```python
import json
from openai import OpenAI

client = OpenAI()
stream = client.chat.completions.create(
    model="gpt-4o",
    messages=[{"role": "user", "content": "北京和上海的天气"}],
    tools=[{
        "type": "function",
        "function": {
            "name": "get_weather",
            "parameters": {
                "type": "object",
                "properties": {"city": {"type": "string"}},
                "required": ["city"],
            },
        },
    }],
    stream=True,
)

# 攒分片：tool_calls 在流式里是 delta 格式,需要拼接
tool_calls_acc: dict[int, dict] = {}  # index → {name, arguments}

for chunk in stream:
    delta = chunk.choices[0].delta
    if delta.tool_calls:
        for tc_delta in delta.tool_calls:
            idx = tc_delta.index
            if idx not in tool_calls_acc:
                tool_calls_acc[idx] = {"name": "", "arguments": ""}
            if tc_delta.function.name:
                tool_calls_acc[idx]["name"] += tc_delta.function.name
            if tc_delta.function.arguments:
                tool_calls_acc[idx]["arguments"] += tc_delta.function.arguments
    elif delta.content:
        print(delta.content, end="", flush=True)

# 流结束后，tool_calls_acc 里就是完整的工具调用
for idx, call in tool_calls_acc.items():
    print(f"\n工具调用 #{idx}: {call['name']}({call['arguments']})")
```

**工程要点**：流式 + 工具调用混合时，`tool_calls` 以 delta 形式分片到达（name 和 arguments 可能分多个 chunk），必须按 index 攒起来拼完再执行。这是实际 Agent 框架（如 LangGraph）里绑不开的底层处理。

## 六、练习题参考答案

<details>
<summary>点击展开 A 类参考要点</summary>

**A1.** 流式输出的核心价值是**压低首字延迟**（TTFT, Time To First Token），从秒级降到百毫秒级。总耗时（全部 token 生成完）基本不变，但用户感知从"卡住了"变成"它在打字"。

**A2.** SSE 适合单向推送（服务端 → 客户端），WebSocket 适合双向交互。LLM 流式输出是典型单向流，SSE 基于 HTTP 更轻量、浏览器原生支持、自动重连，没必要用更重的 WebSocket。

**A3.** 因为调 LLM API 时 90% 时间在等网络 IO（模型推理 + 网络传输），而非 CPU 计算。async/await 让协程在等 IO 时让出控制权，事件循环调度其他协程，一个线程并发处理大量请求，避免为每个请求开线程。

**A4.** ①Semaphore 限流——防止并发太猛触发 API 429 限速；②wait_for 超时——防止慢请求卡死事件循环；③try/except 错误隔离——防止单个协程异常导致整批任务失败。

</details>

<details>
<summary>点击展开 B 类参考思路</summary>

**B1.** 把 `OpenAI()` 换成 `AsyncOpenAI()`，创建调用加 `await`，遍历用 `async for chunk in stream`，整体包在 `async def main()` 里用 `asyncio.run(main())` 启动。

**B2.** 在 `stream_llm` 里加一个计时：用 `asyncio.wait_for(stream.__anext__(), timeout=60)` 包裹每次 chunk 读取，或整体用 `async_timeout.timeout(60)` 上下文管理器，超时时 yield `data: [TIMEOUT]\n\n` 并 return。

**B3.** 用 `asyncio.as_completed(tasks)` 替代 `gather`，每完成一个 future 就调 `on_progress(done, total)`；或保持 gather 但让每个 task wrapper 在 return 前调 callback（注意线程安全用 `asyncio.Lock` 或直接在同一事件循环内无需锁）。

**B4.** 攒完 `tool_calls_acc` 后，对每个 call 执行本地函数，把结果组装成 `role=tool` 的 messages，再调一次 `client.chat.completions.create(stream=False)` 拿到最终自然语言回复。

</details>

<details>
<summary>点击展开 C 类回答要点</summary>

**C1.** 后端用 async generator 逐 chunk 从模型 SDK 接收 token → 包成 SSE 格式（`data: {text}\n\n`）通过 HTTP 长连接推到前端 → 前端用 `EventSource` 或 `fetch` 的 ReadableStream 逐条读取并追加到 DOM。关键链路：模型 SDK（stream=True）→ FastAPI StreamingResponse → HTTP text/event-stream → 前端 EventSource。

**C2.** 骨架：①最初并发没限制，50 条 Eval case 一起飞，API 返回 429；加了 `Semaphore(10)` 后解决。②有一次某条请求模型卡了 2 分钟没返回，整个 batch 等死；加了 `wait_for(timeout=30)` 后超时自动标记失败，不影响其他。③偶发网络异常导致单条抛 `ConnectionError`，用 `try/except` 隔离后整批结果里那条标 error 其他正常返回。一句话收尾："限流、超时、错误隔离这三件套是异步并发的标配。"

**C3.** 流式时 `tool_calls` 以 delta 分片到达（name/arguments 分多个 chunk），我按 index 攒起来拼成完整的函数名+参数 → 流结束后判断有 tool_calls → 执行函数 → 结果以 role=tool 回填 → 再发一次请求继续 stream 后续文本。框架里（如 LangGraph）封装了这段逻辑，但底层就是这套攒-执行-回填的循环。

</details>
