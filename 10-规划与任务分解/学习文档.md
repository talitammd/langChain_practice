# 第10节：规划与任务分解

## 一、本节定位

上一节我们深挖了 ReAct 范式——Thought → Action → Observation 的逐步循环。但 ReAct 是"逐步贪心"的，每步只看当前状态决定下一步，缺乏全局视野。本节解决的问题是：**面对需要十几步甚至几十步才能完成的复杂任务，Agent 怎么先规划再执行、执行中还能动态调整计划？**

学完本节你能：

1. 画出 Plan-and-Execute 三角架构并解释每个角色
2. 对比 ReAct、Plan-and-Execute、ReWOO 三种范式的适用场景
3. 手写一个带 Replan 能力的 Plan-and-Execute Agent
4. 解释层级规划（Hierarchical Planning）和任务树的设计思路

---

## 二、为什么需要规划

### 2.1 ReAct 的局限回顾

| 局限 | 表现 | 后果 |
|------|------|------|
| 逐步贪心 | 每步只看当前状态 | 复杂任务走弯路、死循环 |
| 无全局视野 | 不知道还要做什么 | 跑偏后无法自我修正方向 |
| Token 浪费 | 每步都要完整推理 | 长任务成本爆炸 |

### 2.2 人类做复杂任务的方式

人不会拿到"组织一场 200 人年会"就立刻开始行动。你会先列一个清单：定场地 → 定日期 → 发邀请 → 准备内容 → 彩排 → 执行。做的过程中如果场地不行，你会调整后续计划。Agent 也需要这种能力。

## 三、Plan-and-Execute 架构

### 3.1 三角色模型

```
┌─────────────────────────────────────────────┐
│           Plan-and-Execute 架构              │
│                                             │
│   ┌──────────┐                              │
│   │ Planner  │ 输入: 用户总目标              │
│   │          │ 输出: 有序子任务列表           │
│   └────┬─────┘                              │
│        ▼                                    │
│   ┌──────────┐                              │
│   │ Executor │ 逐个执行子任务                │
│   │          │ (内部可跑 ReAct 循环)          │
│   └────┬─────┘                              │
│        ▼                                    │
│   ┌────────────┐                            │
│   │Re-planner  │ 根据执行结果判断:           │
│   │            │ - 继续下一步？               │
│   │            │ - 修改计划？                 │
│   │            │ - 任务完成？                 │
│   └────────────┘                            │
└─────────────────────────────────────────────┘
```

### 3.2 各角色职责

| 角色 | 输入 | 输出 | 核心能力 |
|------|------|------|----------|
| Planner | 用户目标 + 可用工具描述 | 有序子任务列表 | 任务分解、依赖排序 |
| Executor | 单个子任务 + 工具集 | 子任务执行结果 | 工具调用、ReAct 循环 |
| Re-planner | 原计划 + 已完成结果 + 剩余任务 | 修订后的计划 or "完成" | 计划验证、动态调整 |

### 3.3 与 ReAct 的关系

```
Plan-and-Execute (外层: 全局规划)
    │
    ├── 子任务1 → Executor (内层: ReAct 循环)
    ├── 子任务2 → Executor (内层: ReAct 循环)
    └── 子任务3 → Executor (内层: ReAct 循环)
```

**一句话总结**：Plan-and-Execute 管"做什么"，ReAct 管"怎么做"。不是替代而是互补。

## 四、手撕 Plan-and-Execute Agent

```python
import openai
import json
from typing import List, Optional

# ============ 1. 数据结构 ============
class SubTask:
    def __init__(self, id: int, description: str, status: str = "pending"):
        self.id = id
        self.description = description
        self.status = status  # pending / completed / failed
        self.result: Optional[str] = None

    def __repr__(self):
        return f"[{self.status}] {self.id}. {self.description}"


# ============ 2. Planner ============
def plan(goal: str) -> List[SubTask]:
    """让 LLM 把用户目标分解为子任务列表"""
    response = openai.chat.completions.create(
        model="gpt-4o",
        messages=[{
            "role": "system",
            "content": """你是一个任务规划器。用户会给你一个总目标，
你需要将它分解为 3-7 个有序的子任务。
输出 JSON 数组，每个元素有 id (int) 和 description (string)。
只输出 JSON，不要其他文字。"""
        }, {
            "role": "user",
            "content": f"总目标: {goal}"
        }],
        temperature=0,
        response_format={"type": "json_object"},
    )
    tasks_data = json.loads(response.choices[0].message.content)
    # 兼容 {"tasks": [...]} 或直接 [...]
    task_list = tasks_data if isinstance(tasks_data, list) else tasks_data.get("tasks", [])
    return [SubTask(id=t["id"], description=t["description"]) for t in task_list]


# ============ 3. Executor (简化版) ============
def execute(task: SubTask, context: str = "") -> str:
    """执行单个子任务（简化版：直接让 LLM 生成结果）"""
    response = openai.chat.completions.create(
        model="gpt-4o",
        messages=[{
            "role": "system",
            "content": "你是一个任务执行器。根据已有上下文完成指定子任务，输出执行结果。"
        }, {
            "role": "user",
            "content": f"已完成的上下文:\n{context}\n\n当前子任务: {task.description}"
        }],
        temperature=0,
        max_tokens=1024,
    )
    return response.choices[0].message.content


# ============ 4. Re-planner ============
def replan(
    goal: str,
    completed: List[SubTask],
    remaining: List[SubTask]
) -> tuple[bool, List[SubTask]]:
    """
    根据已完成结果判断是否需要调整计划
    返回: (is_done, updated_remaining_tasks)
    """
    completed_summary = "\n".join(
        f"✅ {t.id}. {t.description} → 结果: {t.result[:200]}"
        for t in completed
    )
    remaining_summary = "\n".join(
        f"⬜ {t.id}. {t.description}" for t in remaining
    )

    response = openai.chat.completions.create(
        model="gpt-4o",
        messages=[{
            "role": "system",
            "content": """你是一个计划审查器。根据总目标、已完成的子任务结果、剩余计划，判断:
1. 总目标是否已经完成？如果是，输出 {"done": true, "tasks": []}
2. 剩余计划是否需要调整？如果需要，输出修改后的剩余任务列表。
3. 如果不需要调整，原样返回剩余任务。
输出 JSON: {"done": bool, "tasks": [{"id": int, "description": str}]}"""
        }, {
            "role": "user",
            "content": f"总目标: {goal}\n\n已完成:\n{completed_summary}\n\n剩余计划:\n{remaining_summary}"
        }],
        temperature=0,
        response_format={"type": "json_object"},
    )
    result = json.loads(response.choices[0].message.content)

    if result.get("done", False):
        return True, []

    new_remaining = [
        SubTask(id=t["id"], description=t["description"])
        for t in result.get("tasks", [])
    ]
    return False, new_remaining


# ============ 5. 主循环 ============
def plan_and_execute(goal: str, max_steps: int = 10) -> str:
    """Plan-and-Execute Agent 主循环"""
    print(f"🎯 目标: {goal}\n")

    # Step 1: 初始规划
    tasks = plan(goal)
    print("📋 初始计划:")
    for t in tasks:
        print(f"  {t}")
    print()

    completed: List[SubTask] = []
    context = ""

    # Step 2: 逐步执行 + Replan
    for step in range(max_steps):
        if not tasks:
            break

        current = tasks.pop(0)
        print(f"▶️  执行: {current.description}")

        # 执行子任务
        result = execute(current, context)
        current.status = "completed"
        current.result = result
        completed.append(current)
        context += f"\n[{current.description}]: {result[:300]}\n"

        print(f"   ✅ 完成\n")

        # Replan: 检查是否需要调整
        is_done, new_remaining = replan(goal, completed, tasks)

        if is_done:
            print("🎉 目标已完成!")
            break

        tasks = new_remaining

    # 汇总最终结果
    final_summary = "\n".join(
        f"{t.id}. {t.description}: {t.result[:200]}" for t in completed
    )
    return final_summary


# ============ 6. 运行示例 ============
if __name__ == "__main__":
    result = plan_and_execute("帮我调研 LangGraph 和 CrewAI 的优缺点，写一份 500 字的对比总结")
    print(f"\n📄 最终结果:\n{result}")
```

### 代码关键点

| 组件 | 作用 | 面试怎么说 |
|------|------|-----------|
| `plan()` | Planner：一次性分解目标为子任务 | 全局规划，减少走弯路 |
| `execute()` | Executor：执行单个子任务 | 生产中可替换为 ReAct Agent |
| `replan()` | Re-planner：每步后动态调整 | 保证计划跟着现实走 |
| `context` | 累积已完成结果作为上下文 | 后续子任务能利用前面的信息 |
| `max_steps` | 安全阀 | 防止无限循环 |

## 五、ReWOO：省钱的变体

### 5.1 核心思想

ReWOO (Reasoning Without Observation) 的策略：**Planner 一次性把所有步骤和依赖全规划好，Executor 按计划机械执行，中间不再回去问 LLM。**

```
传统 Plan-and-Execute:
  Plan → Execute1 → Replan → Execute2 → Replan → Execute3 → ...
  (每步都要调 LLM 做 Replan)

ReWOO:
  Plan(全部步骤 + 依赖关系) → Execute1 → Execute2 → Execute3 → Synthesize
  (中间不调 LLM，只在最后合成答案时调一次)
```

### 5.2 ReWOO 计划格式

```text
Plan: 我需要查找 LangGraph 的特点
#E1 = search("LangGraph 优缺点 2026")

Plan: 我需要查找 CrewAI 的特点
#E2 = search("CrewAI 优缺点 2026")

Plan: 对比两者并写总结
#E3 = llm("根据 #E1 和 #E2 的结果，写一份 500 字对比总结")
```

`#E1`、`#E2` 是占位符，Executor 执行时替换为真实结果。

### 5.3 三种范式对比

| 维度 | ReAct | Plan-and-Execute | ReWOO |
|------|-------|-----------------|-------|
| 规划方式 | 无（逐步决策） | 先规划再执行 | 一次性全规划 |
| LLM 调用次数 | 每步都调 | 执行+Replan 各调 | 仅规划+合成各一次 |
| 动态调整 | 天然支持 | 支持（Replan） | ❌ 不支持 |
| Token 成本 | 高（每步完整上下文） | 中 | 低 |
| 适用场景 | 简单/短任务 | 复杂/需调整的任务 | 路径确定的批量任务 |
| 容错性 | 中 | 高（Replan 修正） | 低（计划错了就全错） |

## 六、层级规划（Hierarchical Planning）

### 6.1 任务树

当任务极其复杂时，单层 Plan-and-Execute 的子任务列表可能过长或过粗。层级规划引入"任务树"概念：

```
根节点: "组织 200 人技术大会"
├── 阶段1: "内容策划"
│   ├── 1.1 确定主题方向
│   ├── 1.2 邀请讲师
│   └── 1.3 审核议题
├── 阶段2: "后勤执行"
│   ├── 2.1 预订场地
│   ├── 2.2 餐饮安排
│   └── 2.3 设备调试
└── 阶段3: "宣传推广"
    ├── 3.1 制作海报
    ├── 3.2 发送邀请
    └── 3.3 社交媒体推广
```

### 6.2 与 Multi-Agent 的关系

层级规划天然适合 Multi-Agent 架构：

- **顶层 Supervisor Agent**：负责阶段划分和进度跟踪
- **中层 Sub-planner Agent**：负责每个阶段的细节规划
- **底层 Worker Agent**：负责具体子任务的执行

这就是后面第 20 节 Multi-Agent 协作的基础。

## 七、面试高频题

### 题目 1：Plan-and-Execute 和 ReAct 有什么区别？什么时候用哪个？

**标准答案**：ReAct 是逐步贪心——每步根据当前状态决定下一步行动，适合短任务和探索性任务。Plan-and-Execute 先全局规划再逐步执行，执行过程中还能 Replan 动态调整，适合需要十几步以上的复杂任务。两者是互补关系：Plan-and-Execute 的 Executor 内部可以跑 ReAct 循环。选型原则——任务步骤少于 5 步用 ReAct 就够了，超过 5 步或有明确阶段性的用 Plan-and-Execute。

---

### 题目 2：Replan 机制为什么重要？没有 Replan 会怎样？

**标准答案**：没有 Replan 就是 ReWOO——一旦初始计划有误，Executor 会机械执行错误计划导致任务失败。Replan 的价值是让 Agent 在执行过程中根据实际结果修正计划方向，就像项目管理的 Sprint Review。它保证了"计划是活的"，能适应执行中发现的新信息。代价是每次 Replan 要多调一次 LLM，但换来的是更高的任务成功率。

---

### 题目 3：ReWOO 适合什么场景？为什么比 Plan-and-Execute 省钱？

**标准答案**：ReWOO 适合路径比较确定、子任务之间依赖关系清晰的批量任务（比如"分别搜索 5 个竞品信息然后写对比报告"）。省钱是因为它只在规划阶段和最终合成阶段各调一次 LLM，中间执行阶段纯工具调用不经过 LLM。但它的容错性差——初始计划有误就全军覆没，所以不适合不确定性高、需要动态调整的任务。

---

### 题目 4：任务分解的颗粒度怎么把握？

**标准答案**：好的子任务应该满足三个标准：1）**可执行性**——每个子任务在当前工具集下能独立完成；2）**原子性**——一个子任务只做一件事，不混合多个动作；3）**有明确产出**——执行完能产生一个可验证的中间结果。颗粒度过粗导致 Executor 内部太复杂容易出错，过细导致计划太长增加成本和出错概率。一般 3-7 个子任务是比较好的范围。

---

### 题目 5：如果 Planner 本身规划错了怎么办？

**标准答案**：三层防御。第一层，Replan 机制——每步执行完检查结果是否合理，发现偏差及时调整。第二层，计划验证——在执行前对计划做一次 sanity check，比如检查子任务之间的依赖是否成环、是否有遗漏的关键步骤。第三层，Human-in-the-loop——对于高风险任务，在初始计划生成后让用户确认再执行。LangGraph 里的 interrupt 机制就是干这个的。

---

### 题目 6：手写 Plan-and-Execute 的伪代码

```python
def plan_and_execute(goal, tools, max_steps=10):
    # 1. 初始规划
    plan = planner(goal, tools)
    completed_results = []

    for _ in range(max_steps):
        if not plan:
            break

        # 2. 取出下一个子任务执行
        task = plan.pop(0)
        result = executor(task, tools, context=completed_results)
        completed_results.append((task, result))

        # 3. Replan: 检查是否需要调整
        is_done, plan = replanner(goal, completed_results, plan)
        if is_done:
            return synthesize(completed_results)

    return synthesize(completed_results)
```

关键点：Planner 只调一次（初始规划），Re-planner 每步后调一次（动态调整），Executor 内部可以是 ReAct 也可以是简单的工具调用。
