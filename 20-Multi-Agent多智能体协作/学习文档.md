# 第20节：Multi-Agent 多智能体协作 — Supervisor、Swarm、角色分工与仲裁

## 一、本节定位

前面所有课程都围绕**单个 Agent**——一个 LLM 驱动的智能体完成所有任务。但复杂任务往往需要多个专精 Agent 协作：一个负责搜索、一个负责写代码、一个负责审查。本节拆解 Multi-Agent 系统的三大架构模式（**Supervisor、Swarm、Hierarchical**），搞清楚何时用哪种、LangGraph 怎么实现、面试怎么答。

---

## 二、为什么需要 Multi-Agent

### 2.1 单 Agent 的瓶颈

| 问题 | 表现 | Multi-Agent 怎么解决 |
|------|------|---------------------|
| 上下文爆炸 | 一个 Agent 承担搜索+编码+审查，Prompt 越来越长 | 每个 Agent 有独立上下文窗口 |
| 能力冲突 | 让一个 Agent 既擅长写代码又擅长写文案，System Prompt 互相矛盾 | 每个 Agent 有专精的 System Prompt |
| 调试困难 | 一个巨型 Agent 出错了不知道哪个环节的问题 | 每个 Agent 独立可测试 |
| 并行受限 | 一个 Agent 串行完成所有子任务 | 多个 Agent 可以并行工作 |

### 2.2 一句话定义

**Multi-Agent 系统 = 多个专精 Agent + 一种协调机制。核心问题不是"怎么做一个 Agent"，而是"多个 Agent 之间怎么分工、怎么通信、谁来兜底"。**

## 三、三大架构模式

### 3.1 Supervisor（监督者模式）

```
                 ┌──────────────┐
                 │  Supervisor  │
                 │  （调度中心）  │
                 └──────┬───────┘
              ┌─────────┼─────────┐
              ▼         ▼         ▼
        ┌──────────┐ ┌──────┐ ┌─────────┐
        │ Searcher │ │Coder │ │Reviewer │
        │ (搜索员)  │ │(码农) │ │(审查员)  │
        └──────────┘ └──────┘ └─────────┘
```

**工作方式**：一个 Supervisor Agent 接收用户任务，决定分配给哪个 Worker Agent，收集结果后汇总。Supervisor 本身也是 LLM 驱动的——它的决策来自模型推理。

**实现（LangGraph）**：

```python
from typing import TypedDict, Annotated, Literal
from langgraph.graph import StateGraph, END, add_messages
from langchain_openai import ChatOpenAI
from langchain_core.messages import HumanMessage, AIMessage, SystemMessage

class SupervisorState(TypedDict):
    messages: Annotated[list, add_messages]
    next_agent: str

# Supervisor：决定下一步交给谁
supervisor_model = ChatOpenAI(model="gpt-4o")

def supervisor_node(state: SupervisorState) -> dict:
    response = supervisor_model.invoke([
        SystemMessage(content="""你是任务调度员。根据对话历史，决定下一步交给哪个 Agent：
        - "searcher": 需要搜索信息
        - "coder": 需要写代码
        - "reviewer": 需要审查代码
        - "FINISH": 任务完成
        只回复 Agent 名称。"""),
        *state["messages"]
    ])
    return {"next_agent": response.content.strip()}

# Worker Agents
def searcher_node(state: SupervisorState) -> dict:
    response = ChatOpenAI(model="gpt-4o").invoke([
        SystemMessage(content="你是搜索专家，负责查找和整理信息。"),
        *state["messages"]
    ])
    return {"messages": [AIMessage(content=f"[搜索结果] {response.content}", name="searcher")]}

def coder_node(state: SupervisorState) -> dict:
    response = ChatOpenAI(model="gpt-4o").invoke([
        SystemMessage(content="你是编程专家，负责编写高质量代码。"),
        *state["messages"]
    ])
    return {"messages": [AIMessage(content=f"[代码] {response.content}", name="coder")]}

def reviewer_node(state: SupervisorState) -> dict:
    response = ChatOpenAI(model="gpt-4o").invoke([
        SystemMessage(content="你是代码审查专家，负责发现 bug 和安全问题。"),
        *state["messages"]
    ])
    return {"messages": [AIMessage(content=f"[审查] {response.content}", name="reviewer")]}

# 路由
def route_supervisor(state: SupervisorState) -> str:
    next_agent = state.get("next_agent", "FINISH")
    if next_agent == "FINISH":
        return END
    return next_agent

# 组装图
graph = StateGraph(SupervisorState)
graph.add_node("supervisor", supervisor_node)
graph.add_node("searcher", searcher_node)
graph.add_node("coder", coder_node)
graph.add_node("reviewer", reviewer_node)

graph.set_entry_point("supervisor")
graph.add_conditional_edges("supervisor", route_supervisor)

# 所有 Worker 执行完回到 Supervisor
for worker in ["searcher", "coder", "reviewer"]:
    graph.add_edge(worker, "supervisor")

app = graph.compile()
```

**优势**：控制集中、易于监控和审计、路由逻辑清晰
**劣势**：Supervisor 是单点瓶颈、每次路由多一轮 LLM 调用

### 3.2 Swarm（群体模式）

```
    ┌──────────┐    Handoff    ┌──────┐
    │ Searcher │──────────────→│Coder │
    └──────────┘               └──┬───┘
         ↑                        │
         │        Handoff         │
         └────────────────────────┘
                                  │ Handoff
                                  ▼
                            ┌─────────┐
                            │Reviewer │
                            └─────────┘
```

**工作方式**：没有中央调度员。每个 Agent 自己决定任务完成后交给谁（Handoff，交接）。Agent A 干完了觉得该让 Agent B 接手，就直接把控制权转给 B。

**实现（LangGraph）**：

```python
from langgraph.prebuilt import create_react_agent
from langgraph.types import Command

# 每个 Agent 有 handoff 工具
def create_handoff_tool(target_agent: str):
    def handoff(reason: str) -> Command:
        """将任务交接给另一个 Agent"""
        return Command(
            goto=target_agent,
            update={"messages": [AIMessage(content=f"[交接给{target_agent}] {reason}")]}
        )
    handoff.__name__ = f"handoff_to_{target_agent}"
    handoff.__doc__ = f"将任务交接给 {target_agent}"
    return handoff

# Searcher 可以交接给 Coder
searcher = create_react_agent(
    model=ChatOpenAI(model="gpt-4o"),
    tools=[search_web, create_handoff_tool("coder")],
    prompt="你是搜索专家。搜索完成后交接给 coder。"
)

# Coder 可以交接给 Reviewer
coder = create_react_agent(
    model=ChatOpenAI(model="gpt-4o"),
    tools=[write_code, create_handoff_tool("reviewer")],
    prompt="你是编程专家。代码写完后交接给 reviewer。"
)

# Reviewer 可以交接回 Coder 或结束
reviewer = create_react_agent(
    model=ChatOpenAI(model="gpt-4o"),
    tools=[create_handoff_tool("coder")],  # 有问题打回
    prompt="你是代码审查专家。有问题交回 coder，没问题直接输出最终结果。"
)
```

**优势**：去中心化、延迟低（不经过中间人）、适合流程固定的场景
**劣势**：流程不透明、调试困难、Agent 之间可能踢皮球

### 3.3 Hierarchical（层级模式）

```
              ┌──────────────────┐
              │  Top Supervisor  │
              └────────┬─────────┘
              ┌────────┴─────────┐
              ▼                  ▼
    ┌──────────────┐    ┌──────────────┐
    │ Research Lead │    │  Dev Lead    │
    │  (研究组长)    │    │  (开发组长)   │
    └──────┬───────┘    └──────┬───────┘
     ┌─────┴─────┐       ┌─────┴─────┐
     ▼           ▼       ▼           ▼
  ┌──────┐  ┌──────┐  ┌──────┐  ┌──────┐
  │Search│  │ Read │  │ Code │  │ Test │
  └──────┘  └──────┘  └──────┘  └──────┘
```

**工作方式**：Supervisor 的扩展——顶层 Supervisor 管多个中层 Supervisor，中层管多个 Worker。适合非常复杂的任务，用子图实现每个 Team。

## 四、三种模式对比

| 维度 | Supervisor | Swarm | Hierarchical |
|------|-----------|-------|-------------|
| 控制结构 | 中心化 | 去中心化 | 层级化 |
| 路由决策 | Supervisor 统一决定 | 每个 Agent 自己决定 | 每层 Supervisor 各管一段 |
| 透明度 | 高（所有决策过 Supervisor） | 低（交接链不直观） | 中等 |
| 延迟 | 每次路由 +1 轮 LLM | 直接交接，延迟低 | 层级越深延迟越高 |
| 适用场景 | 通用、灵活、Agent 数量 < 10 | 流程固定、角色明确 | 大规模、30+ Agent |
| 实现复杂度 | 低 | 中 | 高 |
| 面试频率 | ⭐⭐⭐⭐⭐ | ⭐⭐⭐⭐ | ⭐⭐⭐ |

**面试标准答法**：大多数场景用 Supervisor 就够了——控制集中、易调试、易监控。流程固定的用 Swarm 省掉中间人的开销。任务特别复杂、Agent 特别多才上 Hierarchical。

## 五、Multi-Agent 的工程难题

### 5.1 共享状态 vs 隔离状态

```python
# 方案1：共享 messages（简单但上下文膨胀）
class SharedState(TypedDict):
    messages: Annotated[list, add_messages]  # 所有 Agent 共用

# 方案2：每个 Agent 有私有状态 + 共享通信通道
class AgentState(TypedDict):
    shared_messages: Annotated[list, add_messages]  # 共享通信
    searcher_notes: str   # Searcher 的私有笔记
    coder_draft: str      # Coder 的私有草稿
```

**生产建议**：用子图实现状态隔离。每个 Agent 是一个子图，有自己的 State；主图只传递必要的通信信息（任务描述、结果摘要），不传完整对话历史。

### 5.2 死循环和踢皮球

Agent A 交给 B，B 交回 A，A 又交给 B……必须有终止机制：

```python
class MultiAgentState(TypedDict):
    messages: Annotated[list, add_messages]
    handoff_count: int  # 交接计数器

def supervisor_node(state: MultiAgentState) -> dict:
    if state.get("handoff_count", 0) >= 10:
        # 超过 10 次交接，强制由 Supervisor 直接回答
        return {"messages": [AIMessage(content="已达最大协作轮次，以下是汇总结果...")]}
    # 正常路由...
```

### 5.3 结果汇总与质量控制

多个 Agent 各自产出了结果，怎么汇总？两种方式：

1. **Supervisor 汇总**：把所有 Worker 的输出传给 Supervisor，让它整合成最终答案
2. **专门的 Aggregator 节点**：用代码（不是 LLM）做结构化合并，更可控

## 七、小结 & 下节预告

Multi-Agent 的核心不是"怎么做一个 Agent"，而是**怎么让多个 Agent 高效协作**。三种架构模式各有适用场景：Supervisor 最通用、Swarm 最精简、Hierarchical 最适合大规模。工程上要解决的三大难题是状态管理、死循环控制、结果汇总。

但到目前为止，我们的 Multi-Agent 协作都在**一个系统内部**——同一个 LangGraph 图里的不同节点。如果两个 Agent 运行在不同的系统、不同的框架、甚至不同的公司呢？它们之间怎么通信？这就需要一个跨系统的 Agent 间通信协议——A2A，下节课的内容。

## 八、答案要点

<details>
<summary>概念自测参考答案</summary>

**1.** Supervisor 是中心化调度，所有路由决策由一个中央 Agent 做，适合通用场景和中等规模（< 10 Agent）。Swarm 是去中心化的点对点交接，每个 Agent 自己决定下一步交给谁，适合流程固定、角色明确的场景。Hierarchical 是多层 Supervisor 嵌套，适合大规模（30+ Agent）的复杂系统。

**2.** 三层防护：① 交接计数器，超过阈值强制终止；② Worker 自我判断——如果收到的任务不属于自己的能力范围，拒绝并告知 Supervisor；③ 全局 recursion_limit 兜底。

**3.** 共享状态优势是实现简单、Agent 之间信息流通方便，劣势是上下文膨胀、所有 Agent 的对话混在一起影响模型注意力。隔离状态优势是每个 Agent 的上下文干净、可独立测试，劣势是需要额外的通信机制在 Agent 之间传递必要信息。

**4.** 在 LangGraph 中，Handoff 通过 `Command(goto=target_agent)` 实现——Agent 的节点函数返回一个 Command 对象，指定下一个要执行的节点名称，同时可以附带状态更新。

</details>
