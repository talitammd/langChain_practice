# 第21节：A2A 协议（Agent-to-Agent） — Agent 之间怎么通信，跨系统协作

## 一、本节定位

上节讲了同一个系统内部多个 Agent 的协作。但如果你公司的报销 Agent 需要调用财务部门的审批 Agent，而两个 Agent 运行在不同的系统、不同的框架上呢？MCP 解决的是"Agent 怎么连工具"，A2A 解决的是"**Agent 怎么连 Agent**"。Google 于 2025 年 4 月推出 A2A 协议，2026 年 3 月发布 v1.0 正式版，现已由 Linux Foundation 托管。本节拆解 A2A 的核心概念和它与 MCP 的关系。

---

## 二、A2A 解决了什么问题

### 2.1 MCP 的边界

MCP 让 Agent 把外部工具当作"被动的函数"来调用——Agent 说调什么就调什么，工具没有自主性。但 Agent 不是被动的函数，它有自己的推理能力、自己的状态、自己的执行过程。你不能用"函数调用"的方式去"调用"另一个 Agent。

```
MCP: Agent → 调用 → Tool（被动，无状态，即调即返）
A2A: Agent ↔ 协作 ↔ Agent（主动，有状态，可能耗时很长）
```

### 2.2 A2A 的定位

| 协议 | 解决的问题 | 对象 | 通信模式 |
|------|-----------|------|---------|
| MCP | Agent 怎么连工具 | Agent → Tool | 单向调用 |
| A2A | Agent 怎么连 Agent | Agent ↔ Agent | 双向协作 |

**一句话总结：MCP 是插件接口，A2A 是外交协议。MCP 管你的 Agent 怎么"使用"工具，A2A 管你的 Agent 怎么"委托"另一个 Agent 做事。**

## 三、A2A 的核心概念

### 3.1 Agent Card（Agent 名片）

每个 Agent 需要发布一个 Agent Card，描述自己是谁、能干什么、怎么通信。其他 Agent 通过发现机制获取这张名片，决定是否和它协作。

```json
{
  "name": "财务审批 Agent",
  "description": "处理报销审批、费用核查",
  "url": "https://finance.example.com/a2a",
  "version": "1.0",
  "capabilities": {
    "streaming": true,
    "pushNotifications": true
  },
  "skills": [
    {
      "id": "expense-approval",
      "name": "报销审批",
      "description": "审批员工提交的报销申请",
      "inputModes": ["text", "file"],
      "outputModes": ["text"]
    }
  ],
  "securitySchemes": {
    "oauth2": {
      "type": "oauth2",
      "flows": {
        "clientCredentials": {
          "tokenUrl": "https://auth.example.com/token",
          "scopes": {"expense:approve": "审批报销"}
        }
      }
    }
  }
}
```

**Agent Card 的发现方式**：
- 默认路径：`https://{domain}/.well-known/agent.json`
- Agent Registry（注册中心）查询
- 手动配置

### 3.2 Task（任务）

A2A 中所有协作围绕 **Task** 展开。Task 有完整的生命周期：

```
              submitted
                  │
                  ▼
              working ←──── 重新处理
                  │
          ┌───────┼───────┐
          ▼       ▼       ▼
     completed  failed  input-required
                          │
                          ▼
                     用户/Agent 补充信息
                          │
                          └──→ working
```

| 状态 | 含义 |
|------|------|
| `submitted` | 任务已提交，等待处理 |
| `working` | Agent 正在处理 |
| `input-required` | Agent 需要更多信息（多轮交互） |
| `completed` | 任务完成 |
| `failed` | 任务失败 |
| `canceled` | 任务被取消 |

### 3.3 Message 和 Artifact

```
┌─────────────────────────────────────┐
│                Task                  │
│                                     │
│  Messages（消息）                    │
│  ├── User → Agent: "帮我审批报销"    │
│  ├── Agent → User: "请提供发票"      │
│  └── User → Agent: "发票见附件"      │
│                                     │
│  Artifacts（产出物）                 │
│  ├── 审批结果文档                    │
│  └── 审批流水号                      │
└─────────────────────────────────────┘
```

- **Message**：Agent 之间的对话消息，用于协商和交互
- **Artifact**：任务的最终产出物（文件、结构化数据等）
- **Part**：Message 和 Artifact 的组成部分，支持文本、文件、结构化数据

### 3.4 核心操作

| 操作 | 说明 |
|------|------|
| `message/send` | 向 Agent 发送消息（创建或推进 Task） |
| `message/stream` | 发送消息并流式接收响应 |
| `tasks/get` | 查询 Task 状态 |
| `tasks/cancel` | 取消 Task |

## 四、A2A 的通信流程

### 4.1 基本流程

```python
"""
伪代码：A2A 协议的基本通信流程
"""

# 1. 发现 Agent
agent_card = fetch("https://finance.example.com/.well-known/agent.json")
print(agent_card["skills"])  # 了解对方能做什么

# 2. 认证
token = oauth2_client_credentials(
    token_url=agent_card["securitySchemes"]["oauth2"]["flows"]["clientCredentials"]["tokenUrl"],
    scope="expense:approve"
)

# 3. 发送任务
response = post(
    url=agent_card["url"],
    headers={"Authorization": f"Bearer {token}"},
    json={
        "jsonrpc": "2.0",
        "method": "message/send",
        "params": {
            "message": {
                "role": "user",
                "parts": [
                    {"kind": "text", "text": "请审批这笔报销：金额500元，用途：团队聚餐"}
                ]
            }
        },
        "id": "req-001"
    }
)

# 4. 处理响应
task = response["result"]
print(task["status"]["state"])  # "working" / "completed" / "input-required"

# 如果是 input-required，补充信息继续
if task["status"]["state"] == "input-required":
    response = post(
        url=agent_card["url"],
        json={
            "jsonrpc": "2.0",
            "method": "message/send",
            "params": {
                "message": {
                    "role": "user",
                    "parts": [{"kind": "text", "text": "发票编号：INV-2026-0629"}]
                },
                "taskId": task["id"]  # 关联到同一个 Task
            },
            "id": "req-002"
        }
    )
```

### 4.2 流式和异步

A2A 支持两种长任务模式：

1. **SSE 流式**：`message/stream` 方法，服务端通过 SSE 推送 Task 状态更新和中间结果
2. **Push Notification**：客户端注册一个 Webhook URL，服务端完成后主动回调通知

## 五、A2A vs MCP 完整对比

| 维度 | MCP | A2A |
|------|-----|-----|
| 解决问题 | Agent ↔ Tool | Agent ↔ Agent |
| 通信对象 | 被动的工具/数据源 | 有自主性的 Agent |
| 发现机制 | tools/list（同一进程/连接内） | Agent Card（跨网络发现） |
| 状态 | 无状态（调一次返一次） | 有状态（Task 生命周期） |
| 交互模式 | 单轮：调用→返回 | 多轮：可能需要补充信息 |
| 耗时 | 通常秒级 | 可能分钟到小时 |
| 认证 | 简单（stdio 无认证，HTTP 可选 OAuth） | 强制（OAuth 2.1 / API Key） |
| 推出者 | Anthropic | Google |
| 成熟度 | 生态成熟，广泛采用 | v1.0 刚发布，早期阶段 |

**面试标准答法**：MCP 和 A2A 不是竞争关系，是互补的。MCP 管 Agent 怎么接工具（纵向），A2A 管 Agent 之间怎么协作（横向）。一个完整的企业 AI 系统两者都需要——Agent 用 MCP 接入数据库和 API，用 A2A 与其他团队的 Agent 协作。

## 六、实战：实现一个简单的 A2A Server

```python
"""
用 Python 实现一个简化版的 A2A Server（概念演示）
"""
from fastapi import FastAPI, Request
from uuid import uuid4
import json

app = FastAPI()

# Agent Card
AGENT_CARD = {
    "name": "翻译 Agent",
    "description": "将文本翻译成指定语言",
    "url": "http://localhost:8000/a2a",
    "version": "1.0",
    "skills": [
        {
            "id": "translate",
            "name": "文本翻译",
            "description": "支持中英日韩翻译",
            "inputModes": ["text"],
            "outputModes": ["text"]
        }
    ]
}

# 任务存储
tasks = {}

@app.get("/.well-known/agent.json")
async def get_agent_card():
    """Agent Card 发现端点"""
    return AGENT_CARD

@app.post("/a2a")
async def handle_a2a(request: Request):
    """A2A JSON-RPC 端点"""
    body = await request.json()
    method = body.get("method")
    params = body.get("params", {})
    req_id = body.get("id")
    
    if method == "message/send":
        return handle_message_send(params, req_id)
    elif method == "tasks/get":
        return handle_tasks_get(params, req_id)
    
    return {"jsonrpc": "2.0", "error": {"code": -32601, "message": "Method not found"}, "id": req_id}

def handle_message_send(params, req_id):
    message = params.get("message", {})
    task_id = params.get("taskId") or str(uuid4())
    
    # 提取用户输入
    text = ""
    for part in message.get("parts", []):
        if part.get("kind") == "text":
            text = part["text"]
    
    # 模拟翻译
    translated = f"[翻译结果] {text} → Translation of: {text}"
    
    task = {
        "id": task_id,
        "status": {"state": "completed"},
        "artifacts": [
            {
                "parts": [{"kind": "text", "text": translated}]
            }
        ]
    }
    tasks[task_id] = task
    
    return {
        "jsonrpc": "2.0",
        "result": task,
        "id": req_id
    }

def handle_tasks_get(params, req_id):
    task_id = params.get("id")
    task = tasks.get(task_id)
    if not task:
        return {"jsonrpc": "2.0", "error": {"code": -32602, "message": "Task not found"}, "id": req_id}
    return {"jsonrpc": "2.0", "result": task, "id": req_id}

# 运行：uvicorn a2a_server:app --port 8000
```

### 7.1 企业跨部门协作

```
用户: "帮我出差去上海，预订机票和酒店，报销处理一下"

┌─────────────┐     A2A      ┌──────────────┐

```

## 九、小结 & 下节预告

A2A 协议的核心是让**不同系统、不同框架的 Agent 能够发现彼此、安全通信、协作完成任务**。它和 MCP 共同构成了 2026 年 Agentic AI 的基础设施层：MCP 管纵向（Agent 连工具），A2A 管横向（Agent 连 Agent）。虽然 A2A 的 v1.0 刚发布、生态还在早期，但了解它的设计理念和核心概念是面试中展示技术视野的重要加分项。

## 十、答案要点

<details>
<summary>概念自测参考答案</summary>

**1.** MCP 解决 Agent 怎么接入外部工具和数据源（纵向连接），A2A 解决 Agent 之间怎么发现、通信和协作（横向连接）。互补关系：一个企业 AI 系统中，Agent 用 MCP 访问数据库和 API，用 A2A 与其他团队或公司的 Agent 协作。

**2.** Agent Card 包含：名称和描述、服务 URL、支持的能力（streaming、pushNotifications）、技能列表（每个技能的 ID、名称、输入输出模式）、认证方式。它的作用是让其他 Agent 了解这个 Agent 能做什么、怎么通信，是 A2A 协议的发现机制。

**3.** 状态包括：submitted（已提交）、working（处理中）、completed（完成）、failed（失败）、input-required（需要更多信息）、canceled（已取消）。`input-required` 实现了多轮交互——Agent 处理到一半发现信息不够，暂停并请求补充，Client 补充后 Task 继续执行。

**4.** 因为 Agent 和 Tool 有本质区别：Tool 是被动的、无状态的、即调即返的；Agent 是主动的、有自己的推理能力和状态、执行可能需要很长时间、可能需要多轮交互补充信息。把 Agent 当 Tool 调用会丢失 Agent 的自主性和状态管理能力。

</details>
