# 第12节：工具编排与错误处理

## 一、本节定位

Agent 调用外部工具时，网络抖动、超时、限流、鉴权失败、脏数据等问题不可避免。本节解决：**怎么让 Agent 在工具出错时不崩溃，保持优雅降级和自动恢复？**

---

## 二、工具调用错误的三种类型

| 类型 | 示例 | 处理策略 |
|------|------|----------|
| 瞬时错误 | 网络抖动、临时超时、429 限流 | 指数退避重试 |
| 持久错误 | 403 鉴权失败、404 接口不存在 | 不重试，走降级 |
| 数据错误 | 返回了脏数据、格式不对、值不合理 | 校验 + 清洗 |

## 三、四层防线

### 3.1 第一层：指数退避重试

```python
import asyncio
import random

async def call_with_retry(
    func,
    *args,
    max_retries: int = 3,
    base_delay: float = 1.0,
    max_delay: float = 30.0,
    **kwargs
):
    """
    带指数退避的重试包装器
    - 瞬时错误自动重试
    - 每次延迟翻倍 + 随机抖动
    - 持久错误直接抛出
    """
    last_exception = None
    for attempt in range(max_retries + 1):
        try:
            result = await func(*args, **kwargs)
            return result
        except Exception as e:
            last_exception = e
            error_type = type(e).__name__

            # 判断是否为可重试错误
            retryable = is_retryable_error(e)
            if not retryable or attempt == max_retries:
                raise

            # 指数退避 + 随机抖动
            delay = min(base_delay * (2 ** attempt) + random.uniform(0, 1), max_delay)
            print(f"[Retry {attempt+1}/{max_retries}] {error_type}, 等待 {delay:.1f}s...")
            await asyncio.sleep(delay)

    raise last_exception


def is_retryable_error(e: Exception) -> bool:
    """判断错误是否值得重试"""
    # 429 限流、5xx 服务器错误、超时 → 可重试
    # 403 鉴权失败、404 不存在 → 不可重试
    retryable_keywords = ["timeout", "rate_limit", "429", "502", "503", "connection"]
    error_str = str(e).lower()
    return any(kw in error_str for kw in retryable_keywords)
```

### 3.2 第二层：超时控制

```python
async def call_with_timeout(func, *args, timeout: float = 10.0, **kwargs):
    """给工具调用加超时保护"""
    try:
        result = await asyncio.wait_for(func(*args, **kwargs), timeout=timeout)
        return result
    except asyncio.TimeoutError:
        raise TimeoutError(f"工具调用超时 ({timeout}s)")
```

### 3.3 第三层：降级策略

```python
class ToolExecutor:
    def __init__(self):
        self.cache = {}  # 简化版缓存

    async def execute_with_fallback(self, tool_name: str, *args, **kwargs):
        """带降级的工具执行"""
        try:
            result = await call_with_retry(
                call_with_timeout, self.tools[tool_name],
                *args, timeout=10.0, **kwargs
            )
            self.cache[tool_name] = result  # 缓存成功结果
            return result

        except Exception as e:
            print(f"[Fallback] {tool_name} 失败: {e}")

            # 降级策略1: 静默降级 - 用缓存
            if tool_name in self.cache:
                print(f"  → 使用缓存结果")
                return self.cache[tool_name]

            # 降级策略2: 功能降级 - 换替代工具
            alternatives = self.get_alternatives(tool_name)
            for alt in alternatives:
                try:
                    result = await self.tools[alt](*args, **kwargs)
                    print(f"  → 使用替代工具: {alt}")
                    return result
                except:
                    continue

            # 降级策略3: 优雅降级 - 返回友好提示
            return f"[工具 {tool_name} 暂时不可用] 建议稍后重试"

    def get_alternatives(self, tool_name: str) -> list:
        """获取替代工具"""
        fallback_map = {
            "search_weather": ["search_weather_backup", "search_web"],
            "search_web": ["search_web_backup"],
        }
        return fallback_map.get(tool_name, [])
```

### 3.4 第四层：熔断器模式

```python
import time

class CircuitBreaker:
    """
    熔断器: 连续失败 N 次后跳闸，一段时间后半开试探
    状态: closed(正常) → open(跳闸) → half_open(试探) → closed
    """
    def __init__(self, failure_threshold: int = 5, recovery_timeout: float = 60.0):
        self.failure_threshold = failure_threshold
        self.recovery_timeout = recovery_timeout
        self.failure_count = 0
        self.state = "closed"  # closed / open / half_open
        self.last_failure_time = 0

    async def call(self, func, *args, **kwargs):
        if self.state == "open":
            # 检查是否到了试探时间
            if time.time() - self.last_failure_time > self.recovery_timeout:
                self.state = "half_open"
                print("[CircuitBreaker] 半开状态，试探中...")
            else:
                raise Exception("熔断器开启中，请求被短路")

        try:
            result = await func(*args, **kwargs)
            self._on_success()
            return result
        except Exception as e:
            self._on_failure()
            raise

    def _on_success(self):
        self.failure_count = 0
        if self.state == "half_open":
            self.state = "closed"
            print("[CircuitBreaker] 恢复正常")

    def _on_failure(self):
        self.failure_count += 1
        self.last_failure_time = time.time()
        if self.failure_count >= self.failure_threshold:
            self.state = "open"
            print(f"[CircuitBreaker] 跳闸! 连续失败 {self.failure_count} 次")
```

## 四、错误信息翻译

```python
def translate_error(error: Exception, tool_name: str) -> str:
    """把技术错误翻译成模型能理解的自然语言"""
    error_str = str(error).lower()

    if "timeout" in error_str:
        return f"调用 {tool_name} 超时，可能是网络延迟或服务繁忙。建议稍后重试或使用替代工具。"
    elif "403" in error_str or "auth" in error_str:
        return f"调用 {tool_name} 鉴权失败，可能是 API Key 过期。建议检查配置或跳过此步骤。"
    elif "429" in error_str or "rate" in error_str:
        return f"调用 {tool_name} 被限流，请求过于频繁。建议等待一段时间后重试。"
    elif "404" in error_str:
        return f"调用 {tool_name} 的接口不存在，可能已下线。建议换用其他工具。"
    else:
        return f"调用 {tool_name} 失败: {type(error).__name__}。建议换一种方式尝试。"
```

## 五、幂等性处理

```python
# 非幂等操作的安全重试
executed_ops = set()

async def safe_execute_with_idempotency(op_id: str, func, *args, **kwargs):
    """带幂等性检查的安全执行"""
    if op_id in executed_ops:
        print(f"[Idempotency] 操作 {op_id} 已执行过，跳过")
        return "already_executed"
    result = await func(*args, **kwargs)
    executed_ops.add(op_id)
    return result
```

## 六、面试高频题

### 题目 1：工具调用失败怎么处理？

**标准答案**：先区分错误类型——瞬时错误（超时、限流）用指数退避重试，最多 3 次；持久错误（鉴权失败、接口不存在）不重试直接降级；数据错误靠校验拦截。降级策略三级：先用缓存、再找替代工具、最后优雅降级返回友好提示。生产环境还要加熔断器，连续失败就跳闸保护。

---

### 题目 2：什么是指数退避？为什么要加随机抖动？

**标准答案**：指数退避是每次重试间隔翻倍（1s → 2s → 4s），给故障服务恢复时间。加随机抖动（0-1s）是为了避免多个客户端同时重试造成"惊群效应"——所有请求同时打到恢复中的服务上又把它打挂。

---

### 题目 3：熔断器模式是什么？

**标准答案**：熔断器有三个状态。Closed 正常通行，记录失败次数。连续失败超过阈值就跳到 Open，后续请求直接短路返回失败，不再真正调用。过了恢复时间后进入 Half-Open，放少量请求试探，成功就回到 Closed，失败就继续 Open。就像电闸短路跳闸保护，防止一个挂掉的服务拖垮整个系统。

---

### 题目 4：工具错误信息怎么给模型看？

**标准答案**：不能把原始 stack trace 塞给模型，模型看不懂。要把错误翻译成自然语言——"调用天气接口超时，建议换用搜索工具"。让模型理解错误类型并自主决定下一步：重试、换工具、还是告诉用户。这叫"错误信息可读化"，是 Agent 能自愈的关键。

---

### 题目 5：什么是幂等性？Agent 重试时怎么处理？

**标准答案**：幂等性是指同一个操作执行一次和多次效果相同（如查询、删除）。非幂等操作（如转账、发邮件）重试前必须检查上次是否已执行成功。实现方式是给每个操作分配唯一 op_id，执行前检查是否已在已执行集合中。或者在工具设计层面加幂等 token，服务端去重。
