如果面试官只问你一个问题："什么是 Agent？"你能用一句话回答吗？很多人张口就说"能调工具的大模型"——但这顶多算个 Chain。面试官接着追："那 Agent 和 Workflow、Chain 到底差在哪？"如果你说不清楚，说明你还没触到这个方向最根本的那根弦。今天这一节，我们就来把这个定义问题掰扯清楚。

从阶段 1 走过来，你已经能手搓一个带工具循环的助手了。但那到底算不算 Agent？我们需要一个清晰的标准来判断。

先看 Anthropic 给的定义，这个是目前行业里引用最多的一个分法。他们把所有和大模型相关的自动化系统统称为 Agentic Systems,然后在里面做了一刀切：Workflow 是通过预定义的代码路径来编排大模型和工具的系统——也就是说，走哪条路、调什么工具，是你的代码写死的，模型只负责在每个节点干活。而 Agent，是大模型自己动态决定走哪条路、调什么工具、什么时候停下来。

简单说——Workflow 里做决策的是你的代码；Agent 里做决策的是模型本身。

那 Chain 是什么？Chain 是最简单的一种 Workflow：一条直线，A 调完调 B、B 调完调 C，没有分支、没有循环。你写一个 Prompt 然后格式化输出再调下一个 Prompt，这就是 Chain。

所以这三者的关系可以画成一条自治程度的光谱：左边是 Chain，最死板，纯线性；中间是 Workflow，有分支有条件但路径还是你代码定的；右边是 Agent，模型自己决定路线、自己决定什么时候结束。越往右，模型的自治程度越高,但可控性和可预测性就越低——这是一个工程权衡。

那你上一节写的那个 while 循环助手,算 Agent 吗？算。因为循环里"调不调工具、调哪个、什么时候停"，是模型在做决策，不是你代码写死的。这就是 Agent 的最小形态。

但面试里光能给定义还不够，面试官会接着问："那你在生产里会选哪个？"答案是——不是越 Agent 越好。可预测的任务用 Workflow，因为你能控制它、能测试它、出了问题能复现。只有任务复杂到你没法穷举所有路径的时候，才把决策权交给模型,让它自己当 Agent。大部分生产系统是混合的：外层是 Workflow 编排大流程,某些复杂节点里套一个 Agent 做动态决策。

所以这一节你带走三句话。第一,Agent 的核心定义：模型自己动态决定走哪条路、调什么工具、什么时候停下来——做决策的是模型而非代码。第二,Chain、Workflow、Agent 是一条自治程度光谱：Chain 纯线性、Workflow 预定义分支、Agent 模型自治,越往右越灵活但越难控制。第三,不是越 Agent 越好,生产里按需选型,可预测的用 Workflow,路径不可穷举的才上 Agent,很多系统是两者混合。

定义搞清楚了,接下来一个关键问题就来了：Agent 在循环里到底是怎么"思考"和"行动"的？它靠什么范式来决定下一步干什么？下一节我们就深挖所有 Agent 框架的灵魂——ReAct 范式：Reasoning 加 Acting，思考和行动的交替循环。这是你面试 Agent 岗位必须手撕的核心逻辑。
