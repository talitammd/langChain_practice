先问你一个面试现场最容易翻车的问题：你让大模型返回一个 JSON，它大部分时候返回得好好的，可线上偶尔就给你蹦出一句"好的，这是您要的结果："，再跟一段带注释的伪 JSON，你的程序 json 点 loads 当场抛异常，整条链路崩了。面试官就盯着问你——这种情况你怎么兜底？今天这节，咱们就把这个坑彻底填平。

上一节我们说，Prompt 写得再好，模型吐回来的还是一段自由文本。可 Agent 要调用工具、要把结果传给下一个节点，靠的是字段可靠、能解析的结构化数据，不是一段散文。所以从"能聊天"到"能干活"，结构化输出就是那道关键的坎。

那怎么让模型稳定吐出合法 JSON？这里有三层武器，从弱到强你得分清楚。

最弱的一层叫 JSON Mode，就是告诉模型"请用 JSON 格式回答"。它能保证你拿到的是合法 JSON，但字段对不对、缺不缺，它管不了——这只是约束了形状，没约束内容。

往上一层，是 Function Calling，也就是工具调用。你把想要的参数结构定义成一个函数签名,模型会按这个签名把参数抽出来。这个我们后面会专门讲，它的本质就是一种结构化输出。

而现在最强、也最该写进你简历的一层，叫 Structured Outputs,结构化输出。它直接用 JSON Schema 约束模型,在解码层面就保证输出百分百贴合你定义的 schema，字段、类型、必填项一个都不会错。OpenAI、Claude、Gemini 现在都支持。

讲到这你可能要问，那 Schema 我得手写一大坨 JSON 吗？不用。这就是 Pydantic 登场的地方。你用 Python 定义一个 Pydantic 模型，写清楚每个字段叫什么、是什么类型、是不是必填，它就能自动转成 JSON Schema 喂给模型。模型吐回来之后，你再用同一个模型去校验和解析，类型不对、字段缺失它当场报错——一套定义，约束和校验全包了。

那万一就是校验失败了呢？这就是真正拉开工程师水平的地方。成熟的做法是带重试的兜底：把校验报错信息再塞回给模型，让它"看着错误改一遍"，重试两三次。Instructor 这个库就是干这个的，它把"Pydantic 定义、自动重试、校验"打包好了，生产环境里特别省心。记住面试答题的结构：先 schema 约束，再校验，校验失败带错误信息重试,这才是一套完整的可靠性方案。

所以这一节你带走三句话就够了。第一，结构化输出有三层，JSON Mode 管形状、Function Calling 抽参数、Structured Outputs 用 schema 锁死格式，最后这层最硬。第二，Pydantic 是你的核心工具，一套模型同时搞定 schema 生成和结果校验。第三，永远要有解析失败的兜底，带着错误信息让模型重试,别让一次格式抽风搞崩整条链路。

我们已经能让模型稳定吐出结构化数据了。可光会抽参数还不够——模型到底是怎么"决定"该调哪个函数、怎么把自然语言里的信息精准填进参数的？下一节我们就深挖 Function Calling 的原理,把这套工具调用的机制从里到外拆给你看。这是 Agent 真正长出"手"的那一刻。
