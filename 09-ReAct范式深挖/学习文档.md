## 二、ReAct 是什么

### 2.1 论文背景

ReAct 出自 2022 年 Yao et al. 论文《ReAct: Synergizing Reasoning and Acting in Language Models》。核心贡献：证明让 LLM **交替产出推理轨迹（Reasoning Trace）和外部动作（Action）**，比单纯 Chain-of-Thought 或单纯 Action-only 都效果更好。

### 2.2 三步循环

```
┌─────────────────────────────────────────┐
│             ReAct 循环                   │
│                                         │
│   ┌──────────┐                          │
│   │ Thought  │  模型产出推理文本         │
│   └────┬─────┘                          │
│        ▼                                │
│   ┌──────────┐                          │
│   │  Action  │  决定调什么工具/参数      │
│   └────┬─────┘                          │
│        ▼                                │
│   ┌──────────┐                          │
│   │Observation│ 执行工具，拿到结果       │
│   └────┬─────┘                          │
│        │                                │
│        ▼ 结果回到 Thought，继续循环      │
│        （直到模型决定输出最终答案）       │
└─────────────────────────────────────────┘
```

**一句话总结**：想一步 → 做一步 → 看结果 → 再想下一步。

### 2.3 与 CoT 的对比

| 维度 | Chain-of-Thought (CoT) | ReAct |
|------|------------------------|-------|
| 推理 | ✅ 有（内部思考链） | ✅ 有（Thought） |
| 行动 | ❌ 无（纯文本推理） | ✅ 有（Action → Observation） |
| 信息来源 | 仅靠模型内部知识 | 可查外部工具/API |
| 适用场景 | 数学推理、逻辑题 | 需要查信息/调工具的复杂任务 |
| 出错修正 | 一旦推理链跑偏无法自我修正 | 看到 Observation 后可回头修正 |

**面试金句**：CoT 只能想不能做；ReAct 边想边做边修正。

## 三、ReAct Prompt 模板（原始文本格式）

论文中 ReAct 依赖一个特定的 Prompt 格式来引导模型产出结构化输出：

```text
Answer the following questions as best you can. You have access to the following tools:

{tool_descriptions}

Use the following format:

Question: the input question you must answer
Thought: you should always think about what to do
Action: the action to take, should be one of [{tool_names}]
Action Input: the input to the action
Observation: the result of the action
... (this Thought/Action/Action Input/Observation can repeat N times)
Thought: I now know the final answer
Final Answer: the final answer to the original input question

Begin!

Question: {input}
```

**关键点**：
- `Thought` 是模型自己产出的推理文本
- `Action` 和 `Action Input` 是模型指定的工具调用
- `Observation` 是系统执行工具后注入的结果（不是模型生成的）
- 循环直到模型产出 `Final Answer`

## 四、手撕 ReAct Agent（纯 Python 实现）

这是面试最高频的代码题之一。下面是一个完整的、不依赖任何 Agent 框架的实现：

```python
import openai
import json
import re

# ============ 1. 工具定义 ============
def search_weather(city: str) -> str:
    """模拟天气查询工具"""
    fake_data = {"北京": "32°C 晴", "上海": "28°C 多云", "广州": "35°C 雷阵雨"}
    return fake_data.get(city, f"未找到 {city} 的天气信息")

def calculator(expression: str) -> str:
    """安全计算器"""
    try:
        result = eval(expression, {"__builtins__": {}}, {})
        return str(result)
    except Exception as e:
        return f"计算错误: {e}"

# 工具注册表
TOOLS = {
    "search_weather": {
        "func": search_weather,
        "description": "查询指定城市的天气。参数: city (str)"
    },
    "calculator": {
        "func": calculator,
        "description": "计算数学表达式。参数: expression (str)"
    },
}

# ============ 2. ReAct Prompt 构造 ============
def build_react_prompt(question: str, scratchpad: str = "") -> str:
    tool_desc = "\n".join(
        f"- {name}: {info['description']}" for name, info in TOOLS.items()
    )
    tool_names = ", ".join(TOOLS.keys())

    prompt = f"""Answer the following question as best you can. You have access to these tools:

{tool_desc}

Use EXACTLY this format:

Thought: <your reasoning>
Action: <tool name, one of [{tool_names}]>
Action Input: <input to the tool>

When you have the final answer, use:
Thought: I now know the final answer
Final Answer: <your answer>

Question: {question}
{scratchpad}"""
    return prompt

# ============ 3. 解析模型输出 ============
def parse_output(text: str):
    """解析模型输出，提取 Action/Action Input 或 Final Answer"""
    # 检查是否有 Final Answer
    final_match = re.search(r"Final Answer:\s*(.+)", text, re.DOTALL)
    if final_match:
        return {"type": "final", "answer": final_match.group(1).strip()}

    # 提取 Action 和 Action Input
    action_match = re.search(r"Action:\s*(.+)", text)
    input_match = re.search(r"Action Input:\s*(.+)", text)

    if action_match and input_match:
        return {
            "type": "action",
            "action": action_match.group(1).strip(),
            "action_input": input_match.group(1).strip(),
        }

    return {"type": "error", "raw": text}

# ============ 4. ReAct 主循环 ============
def react_agent(question: str, max_turns: int = 6) -> str:
    """
    ReAct Agent 主循环
    - 每轮: 调LLM获取Thought+Action → 执行工具 → 拼接Observation
    - 直到模型产出 Final Answer 或达到 max_turns
    """
    scratchpad = ""  # 累积的推理轨迹

    for turn in range(max_turns):
        # 构造完整 prompt
        prompt = build_react_prompt(question, scratchpad)

        # 调用 LLM
        response = openai.chat.completions.create(
            model="gpt-4o",
            messages=[{"role": "user", "content": prompt}],
            temperature=0,
            max_tokens=512,
        )
        output = response.choices[0].message.content

        # 解析输出
        parsed = parse_output(output)

        if parsed["type"] == "final":
            print(f"[Turn {turn+1}] Final Answer: {parsed['answer']}")
            return parsed["answer"]

        elif parsed["type"] == "action":
            action_name = parsed["action"]
            action_input = parsed["action_input"]

            # 执行工具
            if action_name in TOOLS:
                observation = TOOLS[action_name]["func"](action_input)
            else:
                observation = f"Error: Unknown tool '{action_name}'"

            # 拼接到 scratchpad
            scratchpad += f"\nThought: {output.split('Thought:')[1].split('Action:')[0].strip() if 'Thought:' in output else ''}"
            scratchpad += f"\nAction: {action_name}"
            scratchpad += f"\nAction Input: {action_input}"
            scratchpad += f"\nObservation: {observation}\n"

            print(f"[Turn {turn+1}] Action: {action_name}({action_input}) → {observation}")

        else:
            print(f"[Turn {turn+1}] Parse error: {parsed['raw']}")
            scratchpad += f"\n{output}\nObservation: Format error, please follow the exact format.\n"

    return "Error: Exceeded max turns without reaching final answer"


# ============ 5. 运行示例 ============
if __name__ == "__main__":
    answer = react_agent("北京今天多少度？如果气温乘以2是多少？")
    print(f"\n最终答案: {answer}")
```

### 代码关键点解读

| 组件               | 作用                                | 面试怎么说                      |
| ---------------- | --------------------------------- | -------------------------- |
| `scratchpad`     | 累积所有历史 Thought/Action/Observation | 相当于 Agent 的"工作记忆"          |
| `parse_output`   | 正则提取 Action 或 Final Answer        | 原始 ReAct 的脆弱点，FC 用 JSON 替代 |
| `max_turns`      | 安全阀，防止无限循环                        | 生产必备，一般 5-10 轮             |
| `temperature=0`  | 让推理确定性更高                          | Agent 场景通常用低温度             |
| `Observation` 注入 | 工具结果由系统插入，不是模型生成                  | 防止模型幻觉伪造结果                 |

## 五、ReAct vs Function Calling：进化关系

```
ReAct (2022, 文本格式)
    │
    │ 问题：格式脆弱、解析靠正则、容易断
    │
    ▼
Function Calling (2023, OpenAI API)
    │
    │ 解决方案：
    │ - Action → 结构化 JSON（tool_calls）
    │ - Action Input → JSON 参数
    │ - 格式由 API 约束，不靠模型自律
    │
    ▼
本质相同：都是 Thought → Action → Observation 循环
只是 Action 的表达方式不同（文本 vs 结构化 JSON）
```

**面试答法**：Function Calling 是 ReAct 模式的工业级结构化实现。底层循环逻辑一样，但 FC 把文本格式的 Action 替换成了 API 层面强约束的 JSON 调用，解决了格式脆弱和解析不稳定的问题。

## 六、ReAct 的局限性与进阶架构

### 6.1 三大局限

| 局限 | 原因 | 后果 |
|------|------|------|
| 长循环注意力漂移 | 上下文越长，早期信息被稀释 | 7-8轮后容易"忘记"初始目标 |
| 逐步贪心缺乏全局规划 | 每步只看当前状态决定下一步 | 复杂任务容易走弯路或死循环 |
| 格式敏感 | 依赖模型严格遵循 T/A/O 格式 | 一旦跳格式整个循环断裂 |

### 6.2 进阶架构：Plan-and-Execute

```
┌─────────────────────────────────────┐
│         Plan-and-Execute             │
│                                     │
│  ┌──────────┐                       │
│  │ Planner  │ 把大任务拆成子任务列表  │
│  └────┬─────┘                       │
│       ▼                             │
│  ┌──────────┐                       │
│  │Executor  │ 每个子任务内部跑 ReAct  │
│  └────┬─────┘                       │
│       ▼                             │
│  ┌──────────┐                       │
│  │Re-planner│ 根据执行结果修订计划    │
│  └──────────┘                       │
└─────────────────────────────────────┘
```

**面试怎么说**：ReAct 擅长单步决策，Plan-and-Execute 在外层加了全局规划能力。Planner 负责"做什么"，Executor（ReAct）负责"怎么做"，Re-planner 负责"做完要不要调整计划"。LangGraph 里的 `create_react_agent` + `Plan-and-Execute` 模板就是这个思路。

## 七、面试高频题

### 题目 1：解释 ReAct 范式的核心思想（概念题）

**标准答案**：ReAct = Reasoning + Acting。让 LLM 在每一步交替产出推理文本（Thought）和外部动作（Action），执行动作后将结果（Observation）回传，继续下一轮推理，形成 T→A→O 循环直到任务完成。核心价值是让模型既能推理又能与外部世界交互，并根据实际结果修正推理方向。

---

### 题目 2：CoT 和 ReAct 的区别是什么？（对比题）

**标准答案**：CoT（Chain-of-Thought）只有 Reasoning 没有 Acting——模型在内部产出思考链但不能调用外部工具；ReAct 在 CoT 基础上加了 Action 和 Observation，模型可以查信息、调工具，并且根据工具返回的真实结果修正推理。通俗说：CoT 只能想不能做，ReAct 边想边做边修正。

---

### 题目 3：ReAct 和 Function Calling 是什么关系？（进化题）

**标准答案**：Function Calling 是 ReAct 的工业级结构化实现。两者底层循环逻辑相同（推理→决定调工具→拿结果→继续推理），区别在于 Action 的表达方式：ReAct 原始方案中 Action 是纯文本（靠正则解析，格式脆弱）；Function Calling 把 Action 标准化为 JSON 格式的 `tool_calls`，由 API 层面约束格式正确性，解决了解析不稳定的问题。

---

### 题目 4：ReAct 有什么局限性？怎么解决？（深挖题）

**标准答案**：三大局限：
1. **长循环注意力漂移**：超过 7-8 轮后模型容易遗忘早期目标。解法：设 max_turns 安全阀 + 摘要压缩历史。
2. **逐步贪心缺乏全局规划**：每步只看当前状态，复杂任务易走弯路。解法：外套 Plan-and-Execute 架构，先规划再执行。
3. **格式敏感**：依赖模型严格按 T/A/O 格式输出，跳格式就断。解法：Function Calling 用 API 约束替代文本格式。

### 题目 5：手写一个 ReAct Agent 的伪代码（手撕题）

**标准答案**：

```python
def react_agent(question, tools, max_turns=6):
    scratchpad = ""
    for _ in range(max_turns):
        prompt = build_prompt(question, tools, scratchpad)
        output = call_llm(prompt)

        if "Final Answer" in output:
            return extract_final_answer(output)

        action, action_input = parse_action(output)
        observation = tools[action](action_input)
        scratchpad += f"Thought: ...\nAction: {action}\nAction Input: {action_input}\nObservation: {observation}\n"

    return "Exceeded max turns"
```

关键点：scratchpad 累积历史、max_turns 防无限循环、Observation 由系统注入而非模型生成。

---

### 题目 6：为什么 Observation 必须由系统注入而不是让模型自己生成？（安全题）

**标准答案**：如果让模型自己生成 Observation，它可能会"幻觉"出一个看起来合理但实际错误的结果，然后基于这个错误结果继续推理，导致最终答案完全不可靠。Observation 由系统执行工具后注入，保证了信息的真实性——这是 ReAct 能比纯 CoT 更准确的核心原因。
