## 一、大模型到底在做什么：预测下一个 Token

### 1.1 一句话本质

LLM 的全部工作，可以浓缩成一句话：

> **给定上文，预测下一个最可能的 token，然后把它接上去，再循环。**

它不"理解"你的问题，而是在做一个超大规模的**概率文字接龙**。理解这一点，后面所有"为什么"都能推导出来。

```
输入: "今天天气真"
        ↓ 模型算出下一个 token 的概率分布
        ↓ {"好": 0.7, "热": 0.15, "冷": 0.1, "棒": 0.05, ...}
        ↓ 采样选出 "好"
输出: "今天天气真好"  ← 把"好"接上，作为新上文，继续预测下一个
```

### 1.2 什么是 Token

Token 是模型眼里的**最小文字单位**。模型不认字，只认被编号的 token。

| 文本 | 大致 token 切分 | 说明 |
|------|----------------|------|
| `artificial` | `art` + `ific` + `ial` | 英文长词会被切成子词 |
| `你好` | `你` + `好` 或 `你好` | 中文通常 1 字≈1-2 token |
| `GPT-4` | `GPT` + `-` + `4` | 符号、数字单独成 token |

> 💡 **面试点**：为什么中文比英文更费 token？因为主流 tokenizer（如 GPT 系列的 BPE）以英文语料为主训练，中文常被切得更碎，同样字数中文消耗的 token 往往是英文的 1.5-2 倍。这直接影响 **API 成本**和**上下文占用**。

## 二、采样参数：控制"放飞还是稳重"的方向盘

模型算出概率分布后，**怎么从分布里挑 token**，由采样参数决定。两个面试必问：

### 2.1 Temperature（温度）

控制分布的"平滑度"，即随机性强弱。

| 温度 | 效果 | 适用场景 |
|------|------|----------|
| 接近 0 | 几乎总选概率最高的，输出确定、可复现 | 抽取、分类、要稳定结果的 Agent 决策 |
| 0.7 左右 | 平衡，有一定多样性 | 通用对话 |
| 1.0+ | 分布被拉平，更随机、更有创造力，也更易胡话 | 创意写作、头脑风暴 |

> ⚠️ **Agent 工程经验**：让 Agent 做工具决策、输出 JSON 时，**温度要调低**（通常 0~0.2），保证结构稳定、可解析、可复现。

### 2.2 Top-p（核采样 / Nucleus Sampling）

只在**累计概率达到 p** 的那一小撮候选 token 里采样，过滤掉长尾"胡话"。

```
概率队列: [0.4, 0.3, 0.2, 0.1]
Top-p = 0.7  →  只在 [0.4, 0.3]（累计 0.7）里选
Top-k = 2    →  只在前 2 个 [0.4, 0.3] 里选（按个数截断）
```

- **Top-p**：按累计概率截断（动态个数）
- **Top-k**：按固定个数截断

> 💡 **面试点**：Temperature 和 Top-p 一般**不建议同时大幅调**，容易互相干扰。常见做法是固定一个调另一个。

## 三、上下文窗口：绕不开的硬约束

模型一次能"看到"的 token 总数有上限，这就是**上下文窗口（Context Window）**。

- 输入 + 输出加起来不能超过窗口大小。
- 超出后，**最前面的内容会被截断、被"遗忘"**。
- 窗口越大，能塞的信息越多，但**计算成本和延迟也越高**（注意力是平方级复杂度）。

> 🔑 **承上启下**：为什么后面要专门学**记忆系统（11节）、上下文工程（13节）、RAG（23节）**？根子全在"窗口装不下所有信息"——这些技术本质都是在解决"在有限窗口里，动态决定喂哪些信息给模型"。

## 四、幻觉：为什么大模型会一本正经地胡说八道（核心考点）

### 4.1 什么是幻觉

**幻觉（Hallucination）**：模型生成**看似合理、实则错误**的内容。注意它不是语法/拼写错误，而是**编造事实**——比如自信地给出一个不存在的论文标题、错误的生日、虚构的 API。

### 4.2 OpenAI 2025 论文的颠覆性结论（面试加分项）

2025 年 9 月，OpenAI 与 Georgia Tech 发表《Why Language Models Hallucinate》，从**统计学角度**给出根因，结论有两条：

1. **预训练的统计必然**：基于"预测下一个 token"的机制，即便训练数据完全无错，统计学习目标本身也会导致一定比例的错误。幻觉源于机制，不是 bug。
2. **评估体系在"奖励猜测"**：现有的 benchmark 大多是"答对得分、答错或不答得 0 分"。这套规则**鼓励模型在不确定时也要蒙一个**，而不是诚实地说"我不知道"。

> 🎯 **一句话记忆**：模型是被"会也要做、不会也要蒙、蒙对了有分"的应试评估体系**教坏的**。

### 4.3 工程上的应对（这才是 Agent 工程师的价值）

既然幻觉**压不到零**，工程上的策略是"控制 + 检测 + 兜底"：

- **降温**：决策/抽取类任务调低 temperature。
- **接外部知识**：用 RAG / 工具调用，让模型基于真实检索结果回答，而不是凭记忆编（这正是 ReAct 的意义）。
- **强制结构 + 校验**：用 JSON Schema / Pydantic 约束输出，解析失败就重试（第 04 节）。
- **引入置信度 / 允许说"不知道"**：在 prompt 和评估里给"承认不确定"留出空间。
- **加 eval**：用评估集量化幻觉率，证明优化有效（第 27 节）。

## 五、代码示例

### 示例 1：用 tiktoken 看清 token 切分与计数

```python
# pip install tiktoken
import tiktoken

# 取 GPT-4 系列使用的编码器
enc = tiktoken.get_encoding("cl100k_base")

samples = ["Hello, world!", "人工智能", "artificial intelligence", "GPT-4 很强"]
for text in samples:
    tokens = enc.encode(text)
    pieces = [enc.decode([t]) for t in tokens]   # 还原每个 token 看切分
    print(f"{text!r:35} → {len(tokens)} tokens | 切分: {pieces}")

# 观察：中文 token 往往比同义英文更多，符号/数字常单独成 token
```

### 示例 2：直观理解 Temperature 对采样的影响（纯 Python，无需联网）

```python
import math, random

# 模型对下一个 token 的"原始打分"（logits）
logits = {"好": 3.0, "热": 1.5, "冷": 1.0, "棒": 0.5}

def softmax_with_temperature(logits: dict, temp: float) -> dict:
    """温度缩放后的概率分布：temp 越大分布越平，越随机"""
    scaled = {k: v / temp for k, v in logits.items()}
    mx = max(scaled.values())                      # 数值稳定性处理
    exp = {k: math.exp(v - mx) for k, v in scaled.items()}
    s = sum(exp.values())
    return {k: round(v / s, 3) for k, v in exp.items()}

for t in [0.2, 1.0, 2.0]:
    print(f"temperature={t}: {softmax_with_temperature(logits, t)}")
# 低温：'好' 概率接近 1（确定）；高温：各 token 概率被拉平（随机）
```

### 示例 3：Top-p 截断逻辑

```python
def top_p_filter(probs: dict, p: float) -> dict:
    """保留累计概率刚好达到 p 的最小候选集合"""
    ordered = sorted(probs.items(), key=lambda x: x[1], reverse=True)
    kept, cum = {}, 0.0
    for token, prob in ordered:
        kept[token] = prob
        cum += prob
        if cum >= p:
            break
    return kept

dist = {"好": 0.4, "热": 0.3, "冷": 0.2, "棒": 0.1}
print("Top-p=0.7 →", top_p_filter(dist, 0.7))   # {'好':0.4,'热':0.3}
```

## 七、本节小结 & 下节预告

**带走三句话**：

- 大模型的本质是**预测下一个 token** 的概率接龙。
- **Temperature 和 Top-p** 是控制随机性的方向盘；做决策/结构化输出要降温。
- **幻觉是机制级的统计必然**，工程上只能"控制 + 检测 + 兜底"，不能根除——这正是 Agent 工程师的价值所在。
