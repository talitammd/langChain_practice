今天一期讲完 AI Agent 工程师必须掌握的全部基础内功——大模型原理、Prompt 工程化、结构化输出、Function Calling、流式输出和异步编程，五个板块一次打通。看完这期，面试里那些"原理层"的追问基本就不慌了。

第一板块：大模型到底在干什么

大模型一辈子只做一件事：根据上文预测下一个最可能的 token。它不是在"理解"你的问题，而是在玩巨型文字接龙——算出下一个 token 的概率分布，挑一个接上去，再把接上的当新上文继续预测。token 就是模型眼里的最小文字单位，一个英文词、半个中文字都可能是一个 token，模型不认字，只认这些被编号的碎片。

那为什么还会编出错误答案？因为模型挑字不是只挑概率最高那个，而是按概率分布采样。两个面试必问的旋钮：Temperature 温度，越高分布越平、输出越随机越有创造力，越低越确定越保守；Top-p，只在累计概率达到 p 的那一小撮候选里挑，过滤掉长尾胡话。这俩就是你控制模型"放飞还是稳重"的方向盘。

把温度调到零幻觉就没了？不会。OpenAI 2025 年底从数学上证明：幻觉是 next-token prediction 的统计必然，训练时评估体系一直在奖励"蒙答案"而非"承认不知道"。说白了模型是被"不会也要蒙、蒙对了有分"的评估方式给教坏的。幻觉压不到零，你能做的是控制它、检测它、用工具兜底——这正是 Agent 工程师存在的意义。

还有一个硬约束：上下文窗口。模型一次能看到的 token 有上限，超了前面就被截断遗忘。后面要学的记忆系统、上下文工程、RAG，根子全在这个窗口装不下所有信息。

第二板块：Prompt 工程的工程化

面试追问来了：线上跑几十个 Prompt，模型一升级全得改，你怎么管？如果答案还停留在"对话框里反复试"，面试官已经给你打叉了。

生产里 Prompt 是要版本管理的工程资产，不是几句随手写的话。三步走：

第一步模板化。把 Prompt 拆成三块——系统指令定角色和规则、用户输入是变量、约束定义控制输出格式。用 Jinja2 模板引擎把变量用占位符填进去，同一模板复用无数场景，改规则只改一处，不用满项目去搜。

第二步版本控制。像管代码一样给每个 Prompt 打版本号，上线前做 A/B 测试拿数据对比，出问题一键回滚到上一个稳定版。LangFuse 就是干这个的。记住：没有版本和回滚的 Prompt，等于在生产环境裸奔。

第三步技巧层。Few-shot 给模型标准示例让它照猫画虎，格式要求高的任务特别有效；Chain-of-Thought 思维链让模型先一步步推理再给答案，复杂任务准确率明显提升。但 Prompt 不是越长越好，token 爆了反而触发中间信息被忽略的问题，精准比冗长重要。

第三板块：结构化输出与 Pydantic

Prompt 写得再好，模型吐回来终究是自由文本。可 Agent 要调工具、传数据给下游节点，靠的是能被程序解析的结构化数据。让模型稳定吐合法 JSON 有三层武器从弱到强：

JSON Mode 只保证合法 JSON，但字段对不对、缺不缺管不了，只约束了形状。Function Calling 按函数签名抽参数，本质也是结构化输出。Structured Outputs 最硬——直接用 JSON Schema 在解码层面锁死格式，字段类型必填项一个都不会错，OpenAI、Claude、Gemini 都支持。

Schema 怎么定义？Pydantic。用 Python 定义模型写清字段名、类型、是否必填，自动转成 JSON Schema 喂给 API；返回后用同一个模型校验解析，类型不对当场报错。一套定义，约束加校验全包。万一校验失败？带重试的兜底——把报错信息塞回给模型让它改一遍，重试两三次。Instructor 库把这套打包好了，生产很省心。面试答题结构：schema 约束 → 校验 → 失败带错误信息重试，三步才完整。

第四板块：Function Calling 原理

核心误区先破：模型自己从来不执行任何函数。它只输出结构化的调用请求——"我想调 get_weather，参数北京"。真正执行函数、查接口、跑代码的是你的应用程序。模型只负责动嘴，干活的是你的代码。

完整流程是三轮对话。第一轮，你把工具定义和用户问题一起发给模型，工具定义就是用 JSON Schema 描述函数名和参数类型。第二轮，模型不直接回答，返回 tool_calls——函数名加它抽取的参数。第三轮，你执行函数把结果回填，模型才用自然语言给最终答复。发问、抽参、回填，三轮闭环。

高频考点——并行工具调用：用户一句话查三个城市天气，模型一轮返回多个 tool_calls，你并发执行再一起回填，省掉多轮往返直接压延迟。保证参数合法靠 strict mode，开了之后 schema 死死约束类型和必填项。

安全层面必须提：模型输出的参数是不可信外部输入。参数校验、权限控制、危险操作加人工确认——把模型输出当用户输入来防，这个意识让面试官觉得你真踩过生产的坑。

第五板块：流式输出与异步编程

你的 Agent 调了模型，五秒后一坨文字糊用户脸上，体验就是"卡了"。流式输出让模型边生成边推 token，首字延迟从几秒压到几百毫秒，体验质变。底层靠 SSE，Server-Sent Events，基于 HTTP 长连接单向推送，生成一个 token 就推一个数据块。为什么不用 WebSocket？大模型输出是单向流，SSE 够了、更轻量、浏览器原生支持。面试记住：单向流选 SSE，双向交互才上 WebSocket。

大模型 API 是典型 IO 密集型调用，同步代码一等线程就卡死。async/await 在等 IO 时让出控制权给事件循环，同一线程并发扛几十上百个请求。Agent 里并行工具调用底层就是 asyncio.gather 并发等多个 IO。

异步生产有三个必踩的坑你得提前知道。第一限流，并发太猛 API 直接 429 限速，用 Semaphore 控制同时发出的请求数。第二超时，一个慢请求卡住了别让它卡死整个循环，asyncio.wait_for 加个超时兜底。第三错误隔离，一个请求抛异常不能炸掉所有并发任务，try/except 包好每个协程。限流、超时、错误隔离——面试讲出这三点就说明你真写过异步生产代码。

五个板块一气打通，你现在有了完整的内功底座：知道大模型的本质和局限、能工程化管理 Prompt、能让模型稳定产出结构化数据、能让模型调用工具并保证安全、能用流式和异步撑住生产级流量。这些就是 Agent 工程师的地基，地基不牢后面的框架和架构全是空中楼阁。下一期是阶段 1 项目实战——把这五块全拼在一起，手写一个不依赖任何框架的极简助手，做完就是一个能写进简历的从零手搓项目。关注我，下期见。
