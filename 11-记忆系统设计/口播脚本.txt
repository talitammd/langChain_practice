面试官问你："你的 Agent 跟用户聊了三十轮对话，到第二十轮用户提了第一轮说的事，你的 Agent 还记得吗？"很多人答"记得啊，我把对话历史全塞 prompt 里"。面试官追一句"上下文窗口只有 128K，三十轮对话加工具调用结果早超了，你塞得下？"这就考你懂不懂 Agent 的记忆系统。

上一节我们讲了 Plan-and-Execute，Planner 拆任务、Executor 执行、Replanner 调整计划。但整个执行过程中产生的大量中间信息——搜索结果、工具返回、推理过程——全堆在上下文里，很快就把窗口撑爆了。怎么存、怎么取、什么时候压缩，这就是记忆系统要解决的问题。

先说清楚 Agent 记忆的两种类型。短期记忆就是当前对话的上下文窗口，里面放着系统指令、对话历史、工具结果，它的特点是快但容量有限——就像人的工作记忆，你同时在脑子里能记的东西就那么多。长期记忆是持久化存在外部的信息，比如向量数据库里存的用户偏好、历史对话摘要，特点是容量大但需要检索——就像人的长期记忆，你得"想一下"才能回忆起来。

那短期记忆装不下了怎么办？最直接的方法是上下文压缩。对话历史太长的时候，用 LLM 把前面的历史摘要成一段 200 字以内的总结，替换掉原始的几千 token。关键技巧是"滚动压缩"——保持最近几轮对话的原文不动，只压缩更早的历史。因为最近的对话信息密度最高，模型需要看到原始措辞才能保持连贯性。

长期记忆怎么建？核心是"写入-检索"两个动作。写入就是 Agent 在对话中主动判断哪些信息值得记住——用户偏好、关键决策、任务结果——然后存到外部数据库。检索就是新一轮对话开始时，用当前问题去向量库里搜相关的历史记忆，把搜到的塞进上下文。这跟 RAG 的思路一模一样，只不过检索的不是文档而是 Agent 自己的历史经验。

面试加分点来了。2026 年最新的研究把 Agent 记忆分成了更细的层次：工作记忆、情景记忆、语义记忆、程序记忆。工作记忆就是上下文窗口；情景记忆是"我上次跟这个用户聊了什么"，按时间线存储的事件；语义记忆是"Python 的列表是可变的"这种事实知识；程序记忆是"处理退款请求要先查订单再验证金额"这种流程性技能。面试时能说出这四层，面试官就知道你不只是看了入门教程。

最后说一个工程实践中经常被忽略的问题——记忆腐蚀。长期运行的 Agent 会积累大量记忆，如果只往里加不清理，检索时噪声越来越大，有用的记忆被淹没在过时信息里。成熟的做法是给记忆设过期时间、做定期清理、还要区分"高置信度记忆"和"临时记忆"。就像人的记忆会遗忘，Agent 也需要有选择性地遗忘。

总结三句话。第一，Agent 记忆分短期和长期——短期是上下文窗口快但有限，长期是外部存储大但需检索。第二，短期记忆装不下就做滚动压缩，保留最近原文、压缩更早历史；长期记忆靠写入加检索，本质是 Agent 自己的 RAG。第三，2026 前沿把记忆分成工作、情景、语义、程序四层，生产里要防记忆腐蚀，有选择性地遗忘过时信息。
