阶段 2 你已经**手撕了 Agent 的全部核心范式**——ReAct、规划、记忆、工具编排、上下文工程、反思修正。但面试官接下来一定会问："那你实际项目用什么框架？"从这节开始进入阶段 3 **框架与协议实战**，第一站就是绕不开的 LangChain。本节目标：搞清 LangChain 2026 年的真实定位，哪些组件值得用、哪些该绕开、它和 LangGraph 到底什么关系。

## 二、LangChain 的前世今生

### 2.1 时间线

| 时间 | 事件 | 意义 |
|------|------|------|
| 2022.10 | Harrison Chase 发布 LangChain | 首个 LLM 应用开发框架，解决了"怎么把大模型串成应用"的问题 |
| 2023 | 爆发式增长，GitHub 8 万星 | 成为事实标准，但 API 频繁变动引大量吐槽 |
| 2024.01 | 拆分为 langchain-core + langchain-community | 核心稳定化，社区集成解耦 |
| 2024.07 | LangGraph 独立发布 | 承认 Chain 模式不够用，图编排成为 Agent 主力 |
| 2025.Q4 | LangGraph 1.0 发布 | 官方明确：Agent 用 LangGraph，LangChain 只做胶水层 |
| 2026.Q1 | LangChain 0.3 + LCEL 稳定 | 92% 的 Agent 岗位 JD 要求 LangGraph，LangChain 退居基础设施 |

### 2.2 一句话定位

**LangChain 是 LLM 应用的基础设施层（模型抽象、Prompt 模板、输出解析、集成连接器），LangGraph 是 Agent 编排层（状态图、循环、人工介入）。两者不是替代关系，而是分层协作。**

## 三、LangChain 的架构拆解

### 3.1 包结构（2026 最新）

```
langchain 生态
├── langchain-core          # 核心抽象：Runnable、LCEL、消息类型、回调
├── langchain                # 高层封装：链、Agent（遗留）、检索器
├── langchain-community      # 社区集成：各种 LLM/向量库/工具的连接器
├── langchain-openai         # OpenAI 专用集成
├── langchain-anthropic      # Anthropic 专用集成
├── langgraph               # 图编排框架（独立包，Agent 的主战场）
├── langsmith               # 可观测性平台（Tracing、Eval）
└── langserve               # 部署为 API（FastAPI 封装）
```

### 3.2 核心抽象：Runnable 与 LCEL

LCEL（LangChain Expression Language）是 LangChain 的管道语法，用 `|` 把组件串成链：

```python
from langchain_core.prompts import ChatPromptTemplate
from langchain_openai import ChatOpenAI
from langchain_core.output_parsers import StrOutputParser

# LCEL 管道：Prompt → LLM → 输出解析
chain = (
    ChatPromptTemplate.from_template("用一句话解释什么是{concept}")
    | ChatOpenAI(model="gpt-4o")
    | StrOutputParser()
)

result = chain.invoke({"concept": "向量数据库"})
print(result)
# "向量数据库是一种专门存储和检索高维向量的数据库，
#  通过相似度搜索实现语义级别的数据匹配。"
```

**LCEL 的 Runnable 协议** — 每个组件都实现统一接口：

```python
# 所有 Runnable 都支持这些方法
chain.invoke(input)          # 同步调用
await chain.ainvoke(input)   # 异步调用
chain.stream(input)          # 流式输出
chain.batch([input1, input2])# 批量调用

# 这意味着任何 Runnable 都可以无缝替换、组合
# 想换模型？只改一行
chain = prompt | ChatAnthropic(model="claude-sonnet-4-20250514") | parser
```

### 3.3 该用的部分

| 组件 | 用途 | 为什么值得 |
|------|------|-----------|
| `ChatPromptTemplate` | Prompt 模板 | 变量注入、消息角色管理，比手拼字符串安全 |
| `ChatOpenAI` / `ChatAnthropic` | 模型抽象 | 统一接口，换模型不改业务代码 |
| `StrOutputParser` / `JsonOutputParser` | 输出解析 | 标准化解析逻辑，支持流式 |
| `RunnablePassthrough` / `RunnableLambda` | 管道工具 | 数据转换、并行执行 |
| 回调系统 | 日志/监控 | 接入 LangSmith 做 Tracing |
| 社区集成 | 连接器 | 几百个现成的 LLM/向量库/工具集成 |

### 3.4 该绕开的部分

| 组件 | 问题 | 替代方案 |
|------|------|---------|
| `AgentExecutor`（旧版 Agent） | 黑盒、调试困难、循环控制弱 | 用 LangGraph |
| `ConversationalChain` | 过度封装，出问题看不到内部 | 自己用 LCEL 组装 |
| `load_tools()` / 预置工具 | 版本混乱、维护不稳定 | 自己写工具函数 |
| `RetrievalQA` | 把 RAG 过度简化，丢失控制力 | 用 LCEL 自己组装检索链 |

**原则：用 LangChain 的抽象层和连接器，不用它的高层封装链。**

## 四、LangChain vs LangGraph：什么时候用哪个

```
┌─────────────────────────────────────────────────┐
│           你的任务需要什么？                       │
│                                                 │
│  线性管道（输入→处理→输出）                        │
│  ├── 是 → 用 LCEL 管道（LangChain）              │
│  └── 否 ↓                                       │
│                                                 │
│  需要循环/条件分支/状态管理？                      │
│  ├── 是 → 用 LangGraph                          │
│  └── 否 ↓                                       │
│                                                 │
│  需要人工介入/中断恢复？                           │
│  ├── 是 → 用 LangGraph + Checkpointer           │
│  └── 否 → LCEL 管道足够                          │
└─────────────────────────────────────────────────┘
```

| 维度 | LangChain（LCEL） | LangGraph |
|------|-------------------|-----------|
| 控制流 | 线性/DAG（有向无环图） | 任意图（支持循环） |
| 状态管理 | 无内置状态 | TypedDict/Pydantic 全局状态 |
| 典型场景 | RAG 管道、简单 QA、数据处理 | Agent、多步任务、审批流程 |
| 人工介入 | 不支持 | 原生 interrupt() + 恢复 |
| 持久化 | 不支持 | Checkpointer 自动保存/恢复 |
| 调试 | 回调 + LangSmith | 状态快照 + LangSmith |

**面试标准答案**：LangChain 管管道，LangGraph 管 Agent。生产里通常两者一起用——LangChain 的模型抽象和 Prompt 模板作为基础设施，LangGraph 做上层编排。

## 五、实战：用 LCEL 构建一个 RAG 管道

```python
"""
用 LCEL 组装一个简单的 RAG 管道
展示 LangChain 的正确用法：用抽象层，不用高层封装
"""
from langchain_core.prompts import ChatPromptTemplate
from langchain_core.runnables import RunnablePassthrough
from langchain_openai import ChatOpenAI, OpenAIEmbeddings
from langchain_core.output_parsers import StrOutputParser
from langchain_community.vectorstores import FAISS

# 1. 准备向量库（模拟）
texts = [
    "LangGraph 是 LangChain 生态中的图编排框架",
    "LCEL 使用 | 管道符串联组件",
    "AgentExecutor 已被 LangGraph 替代",
]
vectorstore = FAISS.from_texts(texts, OpenAIEmbeddings())
retriever = vectorstore.as_retriever(search_kwargs={"k": 2})

# 2. 定义 Prompt 模板
prompt = ChatPromptTemplate.from_template("""
根据以下上下文回答问题。如果上下文中没有答案，说"我不确定"。

上下文：
{context}

问题：{question}
""")

# 3. 用 LCEL 组装管道
#    RunnablePassthrough 保留原始输入，retriever 做检索
rag_chain = (
    {
        "context": retriever | (lambda docs: "\n".join(d.page_content for d in docs)),
        "question": RunnablePassthrough(),
    }
    | prompt
    | ChatOpenAI(model="gpt-4o", temperature=0)
    | StrOutputParser()
)

# 4. 调用
answer = rag_chain.invoke("LangGraph 和 AgentExecutor 是什么关系？")
print(answer)

# 5. 流式调用（同一个链，零改动）
for chunk in rag_chain.stream("LCEL 怎么用？"):
    print(chunk, end="", flush=True)
```

**关键设计点**：

- `retriever` 直接作为 Runnable 嵌入管道，检索结果自动流入 Prompt
- `RunnablePassthrough()` 把用户问题原封不动传给 Prompt 的 `{question}`
- 同一个链支持 `invoke`、`stream`、`ainvoke`、`batch`，不用改代码
- 没有用 `RetrievalQA`，每一步都透明可控

## 六、LangChain 的常见面试题

### Q1：LangChain 和 LangGraph 的关系是什么？

**要点**：LangChain 提供基础设施（模型抽象、Prompt 模板、输出解析、社区集成），LangGraph 提供 Agent 编排（状态图、循环、条件分支、人工介入）。LangChain 是地基，LangGraph 是上层建筑。生产中通常一起用：LangChain 的 `ChatOpenAI` + `ChatPromptTemplate` 作为 LangGraph 节点内的实现。

### Q2：LCEL 的优势是什么？为什么不直接写 Python 函数？

**要点**：Runnable 协议统一了同步/异步/流式/批量四种调用模式，任何组件实现一个接口就自动获得四种能力。管道组合让数据流透明、可追踪（回调系统自动记录每一步）。但对于需要循环和条件分支的场景，LCEL 力不从心，这时要上 LangGraph。

### Q3：为什么不推荐用 AgentExecutor？

**要点**：AgentExecutor 是 LangChain 早期的 Agent 实现，本质是一个 while 循环 + 工具调用。问题在于：循环控制粒度粗（只有 max_iterations）、中间状态不可访问、不支持人工介入、不支持条件分支、调试困难。LangGraph 用显式的状态图替代了隐式的循环，每个节点的输入输出都可检查、可恢复。

### Q4：LangChain 社区集成那么多，生产中怎么选？

**要点**：优先用官方维护的集成包（如 `langchain-openai`、`langchain-anthropic`），它们发版跟得上模型 API 变化。`langchain-community` 里的集成质量参差不齐，用之前先看 GitHub 上最近提交时间和 Issue 数量。关键路径上的组件（模型调用、向量库）宁可自己封装也不要依赖维护不积极的社区包。

## 八、小结 & 下节预告

LangChain 的核心价值在 2026 年已经收敛到三件事：**模型抽象、Prompt 模板、社区集成**。Agent 编排的主战场已经转移到 LangGraph。面试时不要说"我用了 LangChain 做 Agent"，而要说"我用 LangChain 的模型抽象和 Prompt 模板作为基础设施，用 LangGraph 做 Agent 的状态图编排"——一句话就能展示你对生态的理解深度。

那 LangGraph 到底怎么用？状态图、节点、边这些概念听着抽象，实际写起来是什么样？下节课我们直接上手 LangGraph 核心，把图编排从概念变成代码。

## 九、答案要点

<details>
<summary>概念自测参考答案</summary>

**1.** `langchain-core` 是核心抽象层，定义了 Runnable 协议、消息类型、回调系统等基础接口；`langchain` 是高层封装，包含链、旧版 Agent、检索器等；`langchain-community` 是社区贡献的各种 LLM/向量库/工具集成；`langgraph` 是独立的图编排框架，用于构建有状态的 Agent。

**2.** `invoke`（同步单次调用，适合简单请求）、`ainvoke`（异步调用，适合高并发场景）、`stream`（流式输出，适合用户界面实时展示）、`batch`（批量调用，适合离线批处理）。

**3.** ① 循环控制只有 `max_iterations`，无法细粒度控制何时停止或跳转；② 中间状态不可访问，调试时看不到 Agent 每一步的推理过程；③ 不支持人工介入（Human-in-the-loop），无法在关键步骤暂停等人确认；④ 不支持条件分支，所有逻辑靠模型自己决定；⑤ 不支持持久化和中断恢复，进程崩了就得从头来。

**4.** LangChain 的 LCEL 管道适合线性或 DAG（有向无环图）的数据处理流程——输入经过一系列确定的步骤得到输出，没有循环。LangGraph 支持任意图结构，包括循环和条件分支，适合 Agent 这种"走一步看一步、可能回头重试"的场景。

</details>

<summary>动手编码参考答案</summary>

**5.** 翻译链：
```python
from langchain_core.prompts import ChatPromptTemplate
from langchain_openai import ChatOpenAI
from langchain_core.output_parsers import StrOutputParser

translate_chain = (
    ChatPromptTemplate.from_template(
        "将以下文本翻译成{target_language}：\n{text}"
    )
    | ChatOpenAI(model="gpt-4o", temperature=0)
    | StrOutputParser()
)

# 流式调用
for chunk in translate_chain.stream({"text": "Hello world", "target_language": "日语"}):
    print(chunk, end="", flush=True)
```

**6.** 并行调用：
```python
from langchain_core.runnables import RunnableParallel

summary_chain = (
    ChatPromptTemplate.from_template("用一句话总结：{text}")
    | ChatOpenAI(model="gpt-4o") | StrOutputParser()
)
keywords_chain = (
    ChatPromptTemplate.from_template("提取3个关键词（逗号分隔）：{text}")
    | ChatOpenAI(model="gpt-4o") | StrOutputParser()
)

parallel = RunnableParallel(summary=summary_chain, keywords=keywords_chain)
result = parallel.invoke({"text": "LangGraph 是基于状态图的 Agent 编排框架..."})
print(result)  # {"summary": "...", "keywords": "..."}
```

**7.** 异步版本：
```python
import asyncio
from langchain_core.runnables import RunnableLambda

def preprocess(inputs: dict) -> dict:
    return {k: v.strip() if isinstance(v, str) else v for k, v in inputs.items()}

async_translate = RunnableLambda(preprocess) | translate_chain

async def main():
    result = await async_translate.ainvoke({"text": "  Hello world  ", "target_language": "法语"})
    print(result)

asyncio.run(main())
```
