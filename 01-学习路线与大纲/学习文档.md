## 一、先搞清楚：2026 的 AI Agent 工程师到底在做什么

### 1.1 岗位的本质迁移

| 维度 | 2023 年（LLM 应用初期） | 2026 年（Agent 生产化时代） |
|------|------------------------|----------------------------|
| 核心技能 | 会写 prompt、会调 API | 设计能上线的 Agent 系统 |
| 面试重点 | 知道概念（RAG/ReAct 是什么） | 工程落地（怎么控失败、怎么 eval、怎么降本） |
| 交付物 | 能跑通的 demo | 可观测、可回滚、有兜底的生产系统 |
| 关键词 | Prompt Engineering | Context Engineering / Harness Engineering |

**一句话总结**：岗位已经从"会用模型"卷到"会造系统"。

### 1.2 面试官真正在追问的四件事

1. **失败模式**：你的 Agent 调用工具失败、模型输出乱了、陷入死循环，怎么办？
2. **评估（Eval）**：你凭什么说这版比上版好？有没有量化指标？
3. **成本与延迟**：一次任务烧多少钱、跑多久？怎么优化？
4. **安全边界**：怎么防止 Agent 执行危险操作、泄露数据、被 prompt 注入攻击？

> 💡 **划重点**：这四个问题，是本课程每一节都会反复回扣的主线。你能把它们答透，offer 就稳了一半。

## 二、五阶段学习路线详解

```
阶段0 认知校准        →  本节（01）
阶段1 LLM基础内功     →  02-07   打地基，老开发可快进
阶段2 Agent核心范式   →  08-15   ⭐ 面试追问最狠，重点投入
阶段3 框架与协议      →  16-22   ⭐ 对应 92% 岗位 JD
阶段4 RAG与知识工程   →  23-26   企业项目高频
阶段5 生产化与求职    →  27-30   ⭐ 拉开差距的杀手锏
```

### 阶段 1 · LLM 应用基础内功（02-07）
打地基。Token、上下文窗口、幻觉成因、Function Calling、结构化输出、async/异步流式。**已经是开发者的你可以快进，但别跳过 Function Calling 和结构化输出**——它们是 Agent 调工具的命门。

### 阶段 2 · Agent 核心范式（08-15）⭐
本课程的"内功重灾区"。ReAct 循环、规划分解、记忆系统、上下文工程、反思自纠。**这部分要求你手写，不能只调框架**——因为面试官会追问"如果不用 LangGraph 你怎么实现这个循环？"

### 阶段 3 · 框架与协议实战（16-22）⭐
LangGraph（92% 岗位硬要求）、MCP 协议（2026 必考的标准化工具接入）、Multi-Agent 多智能体、A2A 协议。**这是简历项目的主战场。**

### 阶段 4 · RAG 与知识工程（23-26）
向量库、分块策略、混合检索、重排序、GraphRAG。企业级知识库 Agent 的核心。

### 阶段 5 · 生产化与求职冲刺（27-30）⭐
Eval 评估体系、可观测性（LangSmith/Tracing）、降本增效、简历包装与面试题串讲。**最能和"只会调 API 的人"拉开差距的部分。**

## 四、代码示例：30 行看懂"Agent 到底是什么"

很多人学了半天还是不知道 Agent 长什么样。下面用纯 Python（不依赖任何框架）写一个最小 Agent 骨架，让你建立直觉——**Agent 的本质就是一个"思考→调工具→观察→再思考"的循环**。

```python
"""
最小 Agent 骨架：演示 ReAct 思想（伪 LLM，便于本地直接跑通理解结构）
真实场景把 fake_llm 换成对 OpenAI/Claude 等的调用即可。
"""

# 1. 定义工具（Agent 能调用的能力）
def calculator(expr: str) -> str:
    try:
        return str(eval(expr))
    except Exception as e:
        return f"计算出错: {e}"

TOOLS = {"calculator": calculator}


# 2. 伪 LLM：根据当前上下文决定"下一步做什么"
#    真实 LLM 会输出类似 {"action": "calculator", "input": "..."} 的结构
def fake_llm(history: list[str]) -> dict:
    last = history[-1]
    if "需要计算" in last and "结果是" not in "".join(history):
        return {"action": "calculator", "input": "23 * 17 + 8"}
    return {"action": "finish", "input": "23 * 17 + 8 = 399，已算完"}


# 3. Agent 主循环（ReAct 的核心：Reason → Act → Observe 循环）
def run_agent(task: str, max_steps: int = 5):
    history = [f"任务: {task}（需要计算）"]
    for step in range(max_steps):
        decision = fake_llm(history)          # Reason：模型决策
        action, action_input = decision["action"], decision["input"]

        if action == "finish":                # 终止条件
            print(f"✅ 最终答案: {action_input}")
            return action_input

        # Act：执行工具
        observation = TOOLS[action](action_input)
        # Observe：把结果喂回上下文，进入下一轮思考
        history.append(f"调用 {action}({action_input}) 得到: {observation}")
        print(f"第{step+1}步 → {action}({action_input}) = {observation}")

    print("⚠️ 达到最大步数，未完成")


if __name__ == "__main__":
    run_agent("帮我算一下 23 乘 17 再加 8")
```

**运行后你会看到**：Agent 先"想到"要计算 → 调用 calculator 工具 → 拿到结果 → 再判断任务完成 → 输出答案。

> 🔑 **核心认知**：所有花哨的框架（LangGraph、AutoGPT…）剥到底，都是在加强这个循环的三件事——**怎么决策（Reason）、怎么调工具（Act）、怎么管理观察到的信息（Observe/记忆）**。后面的课就是逐个深挖这三块。

1. **Chain**：固定步骤的串联，无决策；**Workflow**：有分支但路径预先编排；**Agent**：由 LLM 自主决定下一步做什么，具备自治性。
2. 不够是因为概念人人会背；考的四件事：失败模式控制、Eval 评估、成本与延迟、安全边界。
3. Prompt 工程关注"单次提问怎么写好"；上下文工程关注"在有限窗口内，动态组织哪些信息（记忆/检索/历史/工具结果）喂给模型"，是系统级问题。
4. LangChain 偏链式封装，复杂流程难以表达循环、分支、人工介入；LangGraph 用图/状态机表达，可控性和可观测性更强，更贴近生产。
5. MCP 把"Agent 怎么接入外部工具/数据"标准化了，过去每个工具都要写一套适配，现在统一协议，工具即插即用。
6-8. 动手题，参照示例结构扩展即可，重点体会"工具注册 → 决策 → 执行 → 兜底"的闭环。
9-11. 开放题，学完阶段 2/5 后你应能答出：结构化输出+解析重试兜底、Eval 量化对比、缓存/模型路由/并行/精简上下文降本。
