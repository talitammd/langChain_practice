# 第19节：MCP 协议（Model Context Protocol） — 2026 必考，标准化工具接入

## 一、本节定位

上两节你已经能用 LangGraph 编排 Agent 了，但每接一个工具（搜索、数据库、文件系统）都要自己写一套接口代码。工具一多维护成本爆炸。MCP（Model Context Protocol）就是来解决这个问题的——它是 Anthropic 于 2024 年底推出的**开放标准**，定义了 AI 模型和外部工具/数据源之间的标准化通信协议。2026 年已经成为 Agent 工具接入的事实标准，面试必考。

---

## 二、MCP 解决了什么问题

### 2.1 没有 MCP 之前

```
Agent 要接入 N 个工具 × M 个模型/框架
= N × M 种接口适配

┌───────────┐     ┌──────────┐
│ ChatGPT   │──→──│ 搜索 API  │  各自实现
│ Claude    │──→──│ 数据库    │  各自实现
│ Gemini    │──→──│ 文件系统  │  各自实现
│ LangGraph │──→──│ GitHub    │  各自实现
└───────────┘     └──────────┘
```

每个模型/框架对接每个工具都要写独立的适配代码。工具换了接口格式，所有客户端都得改。

### 2.2 有了 MCP 之后

```
Agent 只需对接 MCP 协议（一次）
工具只需实现 MCP Server（一次）
= N + M 种适配

┌───────────┐         ┌──────────┐
│ ChatGPT   │         │ 搜索 API  │
│ Claude    │──MCP──→ │ 数据库    │
│ Gemini    │         │ 文件系统  │
│ LangGraph │         │ GitHub    │
└───────────┘         └──────────┘
  MCP Client            MCP Server
```

**一句话总结：MCP 是 AI 工具调用的 USB-C 接口——不管什么设备什么外设，一根线搞定。**

## 三、MCP 的架构

### 3.1 核心角色

| 角色 | 职责 | 类比 |
|------|------|------|
| **Host** | 运行 AI 模型的应用（如 Claude Desktop、Cursor） | 你的电脑 |
| **MCP Client** | 在 Host 内部，负责与 Server 通信 | USB 控制器 |
| **MCP Server** | 暴露工具/资源/Prompt 的独立进程 | U 盘/键盘/打印机 |

### 3.2 三大能力

MCP Server 可以暴露三种能力给 Client：

```python
# 1. Tools（工具）— 模型可以调用的函数
@mcp.tool()
def search_database(query: str) -> str:
    """搜索数据库"""
    return db.search(query)

# 2. Resources（资源）— 模型可以读取的数据
@mcp.resource("file://{path}")
def read_file(path: str) -> str:
    """读取文件内容"""
    return open(path).read()

# 3. Prompts（Prompt 模板）— 预定义的交互模式
@mcp.prompt()
def code_review(code: str) -> str:
    """代码审查 Prompt 模板"""
    return f"请审查以下代码的安全性和性能：\n{code}"
```

| 能力 | 用途 | 控制权 |
|------|------|--------|
| Tools | 模型主动调用，执行操作（搜索、计算、API 调用） | 模型决定何时调用 |
| Resources | 向模型提供上下文数据（文件、数据库记录） | 应用端/用户决定何时加载 |
| Prompts | 标准化的交互模板 | 用户选择使用哪个模板 |

### 3.3 通信协议

MCP 基于 **JSON-RPC 2.0**，支持两种传输方式：

| 传输方式 | 适用场景 | 特点 |
|----------|---------|------|
| **stdio**（标准输入输出） | 本地 Server，Client 和 Server 在同一台机器 | 简单，通过 stdin/stdout 通信 |
| **Streamable HTTP** | 远程 Server，跨网络访问 | 支持 SSE 流式推送，2026 年推荐的远程方案 |

```
通信流程：

Client                          Server
  │                                │
  │── initialize ──────────────→  │  握手：交换版本和能力
  │←── initialize response ─────  │
  │                                │
  │── tools/list ──────────────→  │  发现：获取可用工具列表
  │←── tools list response ─────  │
  │                                │
  │── tools/call ──────────────→  │  调用：执行具体工具
  │←── tool result ─────────────  │
```

## 四、实战：用 FastMCP 写一个 MCP Server

FastMCP 是 MCP 官方推荐的 Python SDK，极大简化了 Server 开发：

```python
"""
weather_server.py — 一个天气查询 MCP Server
"""
from mcp.server.fastmcp import FastMCP

# 创建 MCP Server 实例
mcp = FastMCP("weather-server")

@mcp.tool()
def get_weather(city: str) -> str:
    """获取指定城市的天气信息
    
    Args:
        city: 城市名称（如：北京、上海）
    """
    # 生产中调用真实天气 API
    weather_data = {
        "北京": "晴，32°C，湿度 45%",
        "上海": "多云，28°C，湿度 72%",
        "深圳": "雷阵雨，30°C，湿度 85%",
    }
    return weather_data.get(city, f"暂无 {city} 的天气数据")

@mcp.tool()
def get_forecast(city: str, days: int = 3) -> str:
    """获取未来几天的天气预报
    
    Args:
        city: 城市名称
        days: 预报天数（默认3天）
    """
    return f"{city}未来{days}天：晴→多云→小雨"

@mcp.resource("weather://cities")
def list_cities() -> str:
    """返回支持查询的城市列表"""
    return "北京, 上海, 深圳, 广州, 杭州"

if __name__ == "__main__":
    mcp.run()  # 默认使用 stdio 传输
```

### 4.1 在 Claude Desktop 中使用

在 `claude_desktop_config.json` 中配置：

```json
{
  "mcpServers": {
    "weather": {
      "command": "python",
      "args": ["/path/to/weather_server.py"]
    }
  }
}
```

配置后 Claude 就能自动发现 `get_weather` 和 `get_forecast` 两个工具，用户问天气时 Claude 会自动调用。

### 4.2 在 LangGraph 中集成 MCP

```python

"""

asyncio.run(build_agent_with_mcp())
```

## 五、MCP 的安全模型

### 5.1 信任边界

```
┌─────────────────────────────────────────┐
│ 信任边界                                  │
│                                          │
│  Host ←→ MCP Client   全信任（同进程）    │
│                                          │
│  MCP Client ←→ MCP Server               │
│  ├── 本地 Server（stdio）：中等信任       │
│  └── 远程 Server（HTTP）：低信任          │
│                                          │
│  MCP Server ←→ 外部服务                  │
│  └── 按最小权限原则访问                   │
└─────────────────────────────────────────┘
```

### 5.2 安全原则

1. **用户确认**：敏感操作（写入文件、发送请求）必须经过用户确认
2. **最小权限**：Server 只暴露必要的工具，不要给"可以执行任意 shell 命令"的万能工具
3. **输入校验**：Server 端必须校验所有参数，模型输出的参数是不可信的
4. **传输安全**：远程 Server 必须使用 HTTPS + OAuth 2.1 认证
5. **Prompt 注入防护**：从外部数据源读取的内容可能包含恶意指令，Server 要做清洗

## 七、MCP vs Function Calling

| 维度 | Function Calling | MCP |
|------|-----------------|-----|
| 定义方 | 应用开发者 | MCP Server 提供者 |
| 发现机制 | 手动在代码中注册工具 schema | 自动发现（tools/list） |
| 跨框架 | 每个框架格式不同 | 统一协议，一次实现处处可用 |
| 运行时 | 工具代码在应用进程内 | 工具代码在独立进程/服务中 |
| 安全 | 由应用自己管理 | 协议层定义了信任边界和确认机制 |
| 适用 | 简单场景、少量工具 | 工具多、需要复用、多框架共享 |

**面试标准答案**：Function Calling 是模型层面的工具调用机制，MCP 是应用层面的工具接入标准。Function Calling 告诉模型"你可以调这些函数"，MCP 解决的是"这些函数从哪来、怎么发现、怎么安全调用"。两者是不同层的东西，MCP 的 tools/call 底层用的就是 Function Calling。

## 九、小结 & 下节预告

MCP 的核心价值是**标准化**——让工具的提供者和使用者解耦。Server 开发者写一次工具实现，所有支持 MCP 的客户端都能用；Agent 开发者对接一次 MCP 协议，所有 MCP Server 的工具都能接入。2026 年它已经是 Agent 工具接入的事实标准，不了解 MCP 的面试基本没法聊。

MCP 解决了"Agent 怎么连工具"的问题。那如果一个任务需要多个 Agent 协作——一个负责搜索、一个负责写代码、一个负责审查——它们之间怎么分工和通信？这就是 Multi-Agent 多智能体协作，下节课的内容。

## 十、答案要点

<details>
<summary>概念自测参考答案</summary>

**1.** Tools 的控制权归模型——模型决定何时调用哪个工具；Resources 的控制权归应用端或用户——由应用决定何时加载哪些资源给模型看；Prompts 的控制权归用户——用户选择使用哪个 Prompt 模板。

**2.** stdio 适用于本地 Server，Client 和 Server 在同一台机器上，通过标准输入输出通信，简单但不能跨网络。Streamable HTTP 适用于远程 Server，支持跨网络访问和 SSE 流式推送，需要配合 OAuth 2.1 做认证。

**3.** Schema 约束只保证参数的类型和格式正确（比如 city 是 string），但不保证参数的值合法或安全（比如 city 的值是 `"; rm -rf /"` 这样的注入攻击）。模型输出的参数本质上是不可信的外部输入，Server 必须做业务层面的合法性校验和安全过滤。

**4.** Function Calling 是模型层面的机制，让模型能够输出结构化的工具调用请求，解决的是"模型怎么表达它想调什么工具"。MCP 是应用层面的标准，解决的是"工具从哪来、怎么发现、怎么安全通信"。MCP 的 tools/call 底层可以用 Function Calling 实现。

<summary>动手编码参考答案</summary>

**5.** 待办事项 MCP Server：
```python
from mcp.server.fastmcp import FastMCP

mcp = FastMCP("todo-server")
todos: dict[int, dict] = {}
next_id = 1

@mcp.tool()
def add_todo(title: str) -> str:
    """添加一个待办事项"""
    global next_id
    todos[next_id] = {"id": next_id, "title": title, "completed": False}
    result = f"已添加待办事项 #{next_id}: {title}"
    next_id += 1
    return result

@mcp.tool()
def list_todos() -> str:
    """列出所有待办事项"""
    if not todos:
        return "暂无待办事项"
    lines = []
    for t in todos.values():
        status = "✅" if t["completed"] else "⬜"
        lines.append(f"{status} #{t['id']}: {t['title']}")
    return "\n".join(lines)

@mcp.tool()
def complete_todo(id: int) -> str:
    """标记待办事项为已完成"""
    if id not in todos:
        return f"未找到 #{id} 的待办事项"
    todos[id]["completed"] = True
    return f"已完成 #{id}: {todos[id]['title']}"

@mcp.resource("todo://stats")
def todo_stats() -> str:
    """待办事项统计"""
    total = len(todos)
    done = sum(1 for t in todos.values() if t["completed"])
    return f"总数: {total}, 已完成: {done}, 未完成: {total - done}"

if __name__ == "__main__":
    mcp.run()
```
